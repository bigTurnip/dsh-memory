### 0.3 术语约定

- **对话形态**：agent 在终端/对话环境中输出纯文本，不存在按钮、弹窗、复选框、颜色主题。
- **视图（view）**：同一份记忆数据的不同"输出方式"，不是不同的存储。本文定义三个视图（§3）。
- **序号**：清单中展示的顺序号，会话内有效、可漂移，仅供**指代**使用，不是持久标识。
- **状态标记**：序号后缀的单个 ASCII 字符（`+` / `~` / `-` / `x`），用于纯文本环境下的快速辨识。

## 2. 形态总则（对话形态的 5 条硬规则）

这 5 条是后续所有流程与文案的上位约束，任何单条文案与之冲突都以本节为准。

### G-1 每条应答必须自证

用户读完一条 agent 应答，必须能回答四件事：**它做了什么 / 对象是哪条 / 结果是什么状态 / 怎么反悔或复核**。缺一项即为不合格应答。

### G-2 破坏性操作必须回显正文

删除、批量删除、彻底删除、覆盖式修改，都必须先回显**目标条目的正文**（不是只给序号）。理由：序号会漂移（§2 附注），只给序号等于让用户在盲操作。

> 附注（序号漂移）：清单序号是"当前视图内的位置"。用户说"删掉第 3 条"到系统执行之间，若发生新写入，第 3 条可能已经换人。因此：
> - 序号只在**同一会话内、距上次清单输出不超过一轮**时可信；
> - 超出该条件时，系统必须**先重新输出目标条目正文再执行**，或反问（见 §4-F5 分支 F5-c）；
> - 破坏性操作永远以"回显正文 + 用户确认"为准，不以序号为准。

### G-3 一处编号，两套指代

- **展示序号**（`1+` `2+` 的前缀数字）：供人嘴说，会话内有效、可漂移。
- **条目标识**：稳定、不复用、删除后不回收。**主清单不展示**（保持清单简洁），只在"第 N 条详情 / 第 N 条来源"与 §7.3 的来源标注里出现，供跨会话精确指代。
- 分工：**会话内说序号，跨会话或序号漂移时用标识**。写入回执给序号 + 分层 + 作用域（够用户核对），不给标识（太长且当次无用）。

### G-4 不确定就反问，不猜

指代不唯一（"改掉关于测试那条"命中 2 条）、内容不完整（"记住这个"但无可落地内容）、作用域存疑时，**只允许反问一次**，不允许自行选择一个执行。反问必须是封闭式：给出候选项 + 让用户用序号或原话指代。

### G-5 静默是默认，出声必须付费

自动写入本身**不出声**（OQ-11=A）；出声只允许在三种场合：①用户主动要求记住 ②用户主动查询记忆 ③破坏性操作的回执与确认。其它任何场合的"记忆提示"都算噪声，不允许。

> 设计决策【设计决策，待评审】：为兼顾"用户要能感知写入生效"，允许在**每个会话的前 3 次自动写入**各追加一行极简提示，第 4 次起完全静默。用户可说"以后别提示写入"关闭。该提示预算是交互层策略，不放宽任何业务规则，若评审认为仍太吵可整段删除而不影响任何 AC。

## 3. 视图模型：同一份数据的三种输出

对话形态没有标签页，靠**指令切换视图**。这是本设计解决"删除后要消失 vs 删错了要能恢复"这对矛盾的核心手段（见 §10-C3）。

| 视图 | 触发语句 | 包含哪些状态 | 是否参与检索 | 用途 |
| --- | --- | --- | --- | --- |
| **V-A 主清单**（默认） | "你记得我什么"、"看看你的记忆" | 生效、已修正、已过期 | 仅"生效"参与 | AC-6 的主判定视图 |
| **V-B 回收站** | "看回收站"、"看已删除的记忆" | 已删除-软删 | 否 | 误删恢复（OQ-5=C 可恢复档） |
| **V-C 变更记录** | "第 3 条变更记录"、"看这条的历史" | 该条目的全部历史版本（含已修正） | 否 | AC-3 变更可追溯、AC-2 旧版可查 |

**状态 × 视图可见性矩阵**（工程师与测试都以此为准）

| 状态 | V-A 主清单 | V-B 回收站 | V-C 变更记录 | 检索可返回 | 出现在衍生摘要 |
| --- | --- | --- | --- | --- | --- |
| 生效 | 是 | 否 | 是（作为当前版本） | **是** | 是（受限级除外） |
| 已修正 | 是 | 否 | 是 | 否 | 否 |
| 已过期 | 是 | 否 | 是 | 否 | 否 |
| 已删除-软删 | **否** | 是 | 是 | 否 | 否 |
| 已删除-硬删 | 否 | 否 | 否 | 否 | 否 |

> 硬删行全"否"是 AC-5 与 R-3.6.4 的直接要求：任何视图、任何衍生形态都不出现。审计日志保留"发生过一次隐私删除"这一事实，但不保留正文（AC-5 第四条）。

## 4. 六条主流程

统一模板：**触发语句**（用户原话示例）→ **agent 应答文案**（逐字，`<…>` 为变量）→ **系统行为**（可观察结果）→ **分支**（异常与边界）。

---

### F1 首次自动写入：静默生效

**触发语句示例**（用户没有说"记住"）

```
以后这个项目的注释都用中文写
```

**agent 应答**

不打断当轮主回答。主回答结束后追加一行（受 §2-G-5 提示预算约束）：

```
（已记为项目记忆；说「你记得我什么」可查看）
```

与既有条目冲突时，该行改为：

```
（已更新记忆：注释语言 英文 → 中文；说「第 4 条变更记录」可查看）
```

**系统行为**

1. 按 PRD §3.2 W-a ~ W-d 与 N-1 ~ N-6 做写入判定；命中任一 N 项则**完全静默**（不追加任何行，见 §7.1）。
2. 分层判定：稳定事实与约束 → `语义`；"某天发生了什么" → `情景`。
3. 作用域判定：默认 `项目`（OQ-2=A）；仅当内容是无冲突的跨项目通用习惯（语言、沟通风格）→ `用户`（OQ-6=A）。
4. 去重与冲突：完全重复/语义等价 → 不新增，仅更新"最近确认时间"；直接冲突 → 走 §6-T2（旧条目 `已修正`，新条目 `生效`）。
5. 抽取与写入异步进行，**不阻塞当轮对话**；同会话内立即可被检索，跨会话 30 秒内可被检索（AC-10）。
6. 写入后分配展示序号与稳定标识，但本流程不主动展示（除非用户后续查询）。

**分支**

| 分支 | 条件 | 表现 |
| --- | --- | --- |
| F1-a | 内容只对当前回合有意义（W-b 不满足） | 不写，不提示 |
| F1-b | 无法判断是否敏感 | **不写**（fail-closed），不提示 |
| F1-c | 与既有条目部分补充（细化） | 合并进同一条目，提示行沿用 "已更新记忆" 形态 |
| F1-d | 会话第 4 次及以后的自动写入 | 完全静默，仅可事后查看 |

### F2 用户主动"记住这个"：轻量受理确认

**触发语句示例**

```
记住：这个仓库发版必须先跑 pnpm build
```

**agent 应答（受理成功）**

```
已记住（语义 · 项目，第 4 条）：这个仓库发版必须先跑 pnpm build
```

**agent 应答（内容不足以落成一条）**

```
你想让我记住哪一点？一句话说清就行，比如「发版前必须先跑 pnpm build」。
```

**agent 应答（与既有条目冲突，OQ-4=A）**

```
已更新（语义 · 项目，第 4 条）：发版前先跑 pnpm build
旧版本标为「已修正」：发版前先跑 pnpm test
```

**agent 应答（命中不写清单，如凭据）**

```
这条不记：它看起来是凭据类信息，我不会写入记忆。当前对话照常可用。
```

**系统行为**

1. 用户显式要求是最高显著性信号，优先于任何自动抽取结果。
2. 受理确认**必须在同一轮回复内给出**（PRD §6.4），不得延后到"我稍后记一下"。
3. 作用域与分层判定同 F1，但**内容是可跨项目复用的通用习惯时可落 `用户`**；不确定时落 `项目` 并允许用户后续说"这条升到用户级"。
4. 写入为异步通道，但受理确认不等待写入完成即返回（"已记住"表示已受理，不是已落盘）；若随后写入失败，须在**下一次交互**以 `（上一条没记住成功，可以再说一次）` 显式告知，不得假装成功（见 §7.4）。
5. 回执中同时给出「第 N 条」（可嘴说）与「语义 · 项目」（可核对层次与范围）。

**分支**

| 分支 | 条件 | 表现 |
| --- | --- | --- |
| F2-a | 用户说"记住这个"但没有可说清的内容 | 反问一次（见上），不写 |
| F2-b | 用户明确说"别记住这段/这句话别记" | 应答 `好，这段不记。`，不写不追问（N-2） |
| F2-c | 用户要求记住的内容命中 N-1/N-4/N-5 | 显式回绝一次，说明"不记"而不复述敏感内容 |
| F2-d | 用户要求记住，但该内容与"更早的明确否定"并存 | 以最新一次为准，旧的转 `已修正`，按 F4 回执 |

### F3 查看记忆："你记得我什么"

**触发语句示例**

```
你记得我什么
看看你都记了什么
我的记忆
```

**agent 应答**

输出 §5 规定的清单（完整模板见 §5.3）。最小形态：

```
记忆清单 ｜ 项目 dsh-momery ｜ 共 3 条（生效 3 / 已修正 0 / 已过期 0）

语义层 · 生效 2 条
1+ 发版前必须先跑 pnpm build
   作用域：项目 ｜ 来源：2026-10-30 你说明发版流程时（你明确说的）
   状态：生效
2+ 注释一律写中文
   作用域：用户 ｜ 来源：2026-10-22 你纠正注释语言时（你纠正过的）
   状态：生效

情景层 · 生效 1 条
3+ 10-28 排查过 HMR 不生效，需同时起 dev:web
   作用域：项目 ｜ 来源：2026-10-28 排查会话（你明确说的）
   状态：生效

说「第 N 条详情」看完整内容与来源 ｜ 说「只看项目级」「只看语义层」可筛选
```

**系统行为**

1. **只读操作**：列举**不计入复用次数、不更新最近命中时间**。理由：用户查阅记忆不应人为阻止衰减机制（§3.6），否则"常看的记忆永不衰减"，会使 AC-4 的衰减判定失真。
2. 条数口径：`共 N 条` 统计**未硬删**的条目；分状态小计必须相加等于 N（AC-6 "不多不少"）。
3. 分组顺序固定：`语义` → `情景`；`程序` 不进 MVP，**永不出现空分组标题**。
4. 组内排序：状态优先级 `生效` → `已修正` → `已过期`；同状态内按"最近确认时间"倒序。
5. 不输出稳定标识（太长），仅在"第 N 条详情"时给出。

**分支**

| 分支 | 条件 | 应答 |
| --- | --- | --- |
| F3-a | 无任何记忆（空状态） | `目前没有记录任何关于你的记忆。` 第二行可选：`你在对话里说过、值得长期记住的事，我会自动记下来。` |
| F3-b | 记忆读取超时/失败 | `记忆暂时读不到（超时），这次没法给你清单。可以稍后再问一次。` **不输出空清单冒充"没有记忆"** |
| F3-c | 记忆功能被用户关闭 | `记忆已关闭，我现在没有可查的记忆。说「开启记忆」可以打开。` |
| F3-d | 用户按不存在的维度提问（如"有没有按重要程度分的记忆"） | `记忆不按类型分类，只有分层（语义/情景）和作用域（项目/用户）两个维度。你想看哪一层？`（**B-1 的直接落地**） |

| 档位 | 判定依据 | 执行 | 可恢复性 | 检索 | 审计 |

## 5. 记忆清单展示规范（AC-6 的判定口径）

### 5.1 环境假设与硬规则

| # | 规则 | 理由 |
| --- | --- | --- |
| L-1 | 纯文本行输出，**不使用表格**（不用 `|---|` 网格） | 终端宽度不定，中文双宽字符会使列对齐错位 |
| L-2 | **不依赖颜色**区分状态（颜色可加，但不得是唯一手段） | 无障碍；且大量终端不支持 |
| L-3 | **不使用 emoji 与图形符号**（`🔒`、`✅`、`⬤` 等） | 宽度不可预测，跨终端渲染不一致；屏幕阅读器读法不统一 |
| L-4 | 状态标记使用**单个 ASCII 字符**后缀（`+` `~` `-` `x`） | 可 grep、可断言、无宽度歧义 |
| L-5 | 单行显示宽度目标 ≤ 76 列（中文按 2 列计）；超出则换行，续行缩进 5 空格 | 80 列终端安全 |
| L-6 | 字段分隔使用全角竖线 `｜`，不使用空格对齐 | 避免双宽字符导致的对齐漂移 |
| L-7 | 条目之间**空行分隔**，不使用连续紧凑列表 | 多行条目混合时更易扫读 |

### 5.2 条目结构（字段顺序固定，**每条固定三行**）

```
<序号><状态标记> <内容>
   作用域：<项目|用户> ｜ 来源：<YYYY-MM-DD> <事件短语>（<来源标注>）
   状态：<状态文字>
```

- 第 1 行缩进 0；第 2、3 行缩进 4 空格（对齐到内容起始，与序号宽度无关，避免两位数序号导致漂移）。
- 第 1 行超宽时续行缩进 4 空格，仍算"第 1 行内容"的延续。
- `状态标记`： `+` 生效、`~` 已修正、`-` 已过期、`x` 已删除（仅 V-B 回收站）。
- **`状态：` 永远独立成行**——这是刻意的：状态是断言与扫读的主目标，独立成行能让测试按行 grep，也避免长状态文字（含取代关系/到期日）把整条挤到 100+ 列。

**为什么是这个字段顺序**：序号→内容，是最短路径地让人确认"这是不是我说的那条"；作用域→来源→状态，是"这条能管多宽、凭什么可信、现在还算不算数"的固定三段。AC-6 要求的五个要素（分层、内容、作用域、来源、状态）全部落在这三行里，其中**分层在分组标题**里给出。

### 5.3 完整模板（含全部状态的样例）

```
记忆清单 ｜ 项目 dsh-momery ｜ 共 6 条（生效 4 / 已修正 1 / 已过期 1）

语义层 · 生效 3 条
1+ 发版前必须先跑 pnpm build
   作用域：项目 ｜ 来源：2026-10-30 你说明发版流程时（你明确说的）
   状态：生效
2+ 注释用中文，测试文件用英文
   作用域：用户 ｜ 来源：2026-10-22 你纠正注释语言时（你纠正过的）
   状态：生效
3+ 测试命令是 vitest
   作用域：项目 ｜ 来源：2026-10-30 你纠正测试命令时（你纠正过的）
   状态：生效

语义层 · 已修正 1 条
4~ 测试命令是 jest
   作用域：项目 ｜ 来源：2026-10-25 你说明测试命令时（你明确说的）
   状态：已修正（2026-10-30 被第 3 条取代）

情景层 · 生效 1 条
5+ 10-28 排查过 HMR 不生效，需同时起 dev:web
   作用域：项目 ｜ 来源：2026-10-28 排查会话（你明确说的）
   状态：生效

情景层 · 已过期 1 条
6- 10-20 排查过 pnpm 安装超时，换镜像解决
   作用域：项目 ｜ 来源：2026-10-20 排查会话（你明确说的）
   状态：已过期（2026-11-19 到期，不参与检索）

回收站另有 1 条已删除（可恢复），不计入上面的 6 条；说「看回收站」查看

说「第 N 条详情」看完整内容与来源 ｜ 说「只看项目级」「只看语义层」可筛选 ｜ 说「看已过期的」可单独查看
```

> 说明：上面这 6 条（+ 回收站 1 条）覆盖 2 个分层 × 2 个作用域 × 4 个状态，可直接作为 AC-6 的测试夹具（fixture）。

### 5.4 分组规则

1. **分组只按分层**：`语义层` → `情景层`；层名后跟"该层在当前视图中的状态小计"。
2. **不出现空分组**：某层无条目就不打印该层的任何标题（B-2）。
3. **组内再分状态小节**：`生效` → `已修正` → `已过期` 三个小标题，无条目的省略。
4. **分页不切断分组**：换页时在新页首**重印所属分层与状态小标题**，避免条目脱离上下文（这是 L-1 不用表格的另一个原因）。

### 5.5 状态在纯文本里的可辨识设计（AC-4 / D-3 的关键）

三通道冗余，任一通道单独可判：

| 通道 | 生效 | 已修正 | 已过期 | 已删除（软删） |
| --- | --- | --- | --- | --- |
| ① 序号后缀字符 | `+` | `~` | `-` | `x` |
| ② 状态字段文字 | `状态：生效` | `状态：已修正（<日期> 被第 N 条取代）` | `状态：已过期（<日期> 到期，不参与检索）` | `状态：已删除（可恢复）` |
| ③ 所在小节标题 | `· 生效 k 条` | `· 已修正 k 条` | `· 已过期 k 条` | 仅在 V-B 出现 |

要点：
- `~` 的语义提示是"被改写过"，`-` 的语义提示是"不再算数"，二者字符形态不同且都不与 `+` 混淆。
- `已修正` 必须带**取代关系**（被第几条取代）与日期，否则用户无法判断哪个说法现在有效（AC-2/AC-3）。
- `已过期` 必须带**到期日期**并声明"不参与检索"，否则用户会误以为它仍在起作用（AC-4）。
- 状态标记与状态字段**同时存在**，是为了满足 L-2：任何单一通道失效（颜色、字体、复制粘贴丢失格式）时仍可判定。

### 5.6 条数、分页与截断（AC-6 "不多不少"的实现口径）

| 项 | 规则 |
| --- | --- |
| 总数行 | 首行必须给 `共 N 条`，且 **`生效 a + 已修正 b + 已过期 c = N`**（即 V-A 可见集合）。**N 与各分项必须与实际一致，不得估算**。 |
| 回收站计数 | 软删条数**单独一行**报告（`回收站另有 k 条…`），**不计入 N**——因为 §3 可见性矩阵规定软删不在 V-A 出现 |
| V-A 每页上限 | **10 条**（跨分组连续计数） |
| 分页提示 | 有下一页时末尾输出：`说「继续」看第 11-20 条`；最后一页输出：`已到最后一页` |
| 单页内条目完整性 | 一个条目不得跨页拆开（多行条目整体放到下一页） |
| 内容行截断 | 内容可用宽度超 2 行（≈140 显示列）时截断，追加 `…`，并在末尾提示 `说「第 N 条详情」看完整内容` |
| 已过期条目上限 | V-A 中已过期最多展示 5 条，超出以 `已过期另有 k 条，说「看已过期的」分页查看` 汇总；**仍计入 N 与 c** |
| 回收站上限 | 每页 10 条，规则同上 |
| 排序稳定性 | 同一会话内连续两次清单，若期间无写入/修改/删除，序号必须完全一致（可测试） |

> **"不多不少"的准确含义**：不要求一次把所有条目打印完，而要求**首行声明的 N 等于 V-A 可见集合（生效+已修正+已过期）的实际条数**，且分页各页并集恰好等于该集合、无重复无遗漏；软删条数另行列示、不计入 N。§10-C2 说明了这一点与分页上限之间的张力及裁定。

### 5.7 空状态与异常态

| 场景 | 文案 | 备注 |
| --- | --- | --- |
| 无任何记忆（V-A） | `目前没有记录任何关于你的记忆。` | AC-6 指定文案，**逐字** |
| 空但已有记忆被全部删除 | `目前没有生效中的记忆。回复「看回收站」可以查看已删除的 3 条。` | 不得让用户以为数据丢了 |
| 回收站为空 | `回收站是空的。` | — |
| 读取失败 | `记忆暂时读不到（超时），这次没法给你清单。可以稍后再问一次。` | 禁止用空状态文案冒充读取失败 |
| 功能关闭 | `记忆已关闭，我现在没有可查的记忆。说「开启记忆」可以打开。` | — |
| 筛选后为空 | `项目级记忆目前是 0 条。说「看全部」可看所有分层。` | 必须提示如何回到全集，避免用户误判"记忆丢了" |

### 5.8 筛选（无面板时的实现口径）

AC-6 要求"清单可按作用域/分层筛选"。对话形态下**筛选 = 带限定词重述查询**：

| 用户语句 | 行为 | 输出差异 |
| --- | --- | --- |
| `只看项目级的` | 作用域 = 项目 | 首行改 `记忆清单（项目级）｜ 项目 dsh-momery ｜ 共 3 条（…）`，条数改按筛选后集合计 |
| `只看用户级的` | 作用域 = 用户 | 同上 |
| `只看语义层` / `只看情景层` | 分层过滤 | 首行补限定词，只打印该层 |
| `看已过期的` | 状态过滤（AC-4 的查看入口） | `记忆清单（已过期）｜ … 共 1 条` |
| `看回收站` | 切 V-B | `回收站 ｜ 共 1 条（可恢复）` |
| `看全部` | 清空筛选，回 V-A 首页 | — |
| `不要筛选了` / `回到全部` | 同上 | — |

规则：
1. 筛选是**会话内的临时上下文**，只影响下一次及之后紧邻的查询；用户说"看全部"或发起新话题即失效。
2. 筛选后的 `共 N 条` 是**筛选后集合**的条数，不是全集；首行必须带 `（项目级）` 之类的限定词，避免与全集混淆。
3. 筛选**不接受类别维度**（B-1）：用户问"能不能按重要程度看"→ 见 F3-d 话术。
4. 筛选不做组合语法发明：`只看项目级的语义层` 这类复合表达**可以支持**，但不要求；不支持时应答 `我可以按范围或按分层筛选，一次一个，你要哪个？`

### 5.8b 作用域在清单上的表达（AC-8 的可见性口径）

AC-8 要求"P1 的项目级记忆不出现在 P2"。在对话形态下，这靠**首行的工作目录声明**来让用户可判定，而不是靠界面隔离提示：

1. V-A 首行必须印当前工作目录名：`记忆清单 ｜ 项目 dsh-momery ｜ 共 6 条（…）`。
2. 项目级条目只反映**当前工作目录**的条目；切换工作目录后，清单里的项目级部分随之变化——这是 AC-8 的用户可观察面。
3. 用户级条目跨目录始终可见（OQ-6=A）。
4. 用户在当前目录询问"另一个项目的记忆"时：应答 `项目级记忆只在对应工作目录里可见。切到那个项目再问，或者问用户级的。`——**不得跨项目读取**（R-3.4.1/AC-8）。
5. 首行的项目名是**判定锚点**：测试断言"切换工作目录后首行项目名变化，且项目级条目集合随之变化，用户级条目不变"。

> 为什么不用"筛选器显示当前作用域"：对话形态没有筛选器状态栏。首行的工作目录名是唯一稳定的、可被用户与测试同时读取的锚点。

### 5.9 指令词表（**权威**，实现与测试的唯一对表）

MVP 的指令全部来自自然语言，但**这些词必须被识别**；识别不了的表达必须按本节「兜底规则」处理，不得静默误解。

> 「最小必需」= 是：MVP 不识别即视为缺陷；可选：可不实现，但实现了必须符合本节文案。

| 查看清单 | `你记得我什么`、`看看你的记忆`、`我的记忆`、`你记得什么` | F3 / V-A | 是 |
| 筛选·作用域 | `只看项目级的`、`只看用户级的` | §5.8 | 是 |
| 筛选·分层 | `只看语义层`、`只看情景层` | §5.8 | 是 |

| 翻页 | `继续`、`下一页` | §5.6 | 是 |
| 切回收站 | `看回收站`、`看已删除的记忆` | F5 / V-B | 是 |

| 删除（隐私） | `彻底删除`、`永久删除`、`不要留副本`（**D-8 X-1：仅显式不可逆措辞触发；「忘掉」已移出本行**） | F5 | 是 |

| 开关 | `开启记忆`、`关闭记忆` | §5.7 | 是 |

**兜底规则**：用户表达上述任一意图但用词不在表内时，**先按最接近的意图复述确认**，不得静默执行破坏性操作。示例：

```
你想让我把第 3 条从记忆里去掉，对吗？回复「确认删除」执行，回复「取消」放弃。
```

**反向规则**：用户说「确认」但当前没有待确认的操作时，应答 `现在没有待确认的操作。说「你记得我什么」可查看记忆。`——不得把游离的「确认」当作任何默认动作的授权。

## 6. 状态机

### 6.1 状态定义与不变量

| 状态 | 标记 | 含义 | 检索可返回 | 可出现在 V-A | 终态 |
| --- | --- | --- | --- | --- | --- |
| 生效 ACTIVE | `+` | 当前有效、参与检索与排序 | 是 | 是 | 否 |
| 已修正 SUPERSEDED | `~` | 被更新的说法取代，保留作变更史 | 否 | 是 | 否 |
| 已过期 EXPIRED | `-` | 超出保留期，不再参与检索与排序 | 否 | 是 | 否 |
| 已删除-软删 DELETED_SOFT | `x` | 用户普通删除，可恢复 | 否 | 否（仅在 V-B） | 否 |
| 已删除-硬删 DELETED_HARD | （无） | 隐私删除，不可恢复、不可见 | 否 | 否 | **是** |

**不变量**

- I-1 任意条目同一时刻只处于一个状态。
- I-2 `检索候选集 ≡ {状态 = 生效}`。**任何检索实现只有这一个来源，不存在例外**（这条让 AC-2/AC-3/AC-4/AC-5 的"不再返回"全部可判定）。
- I-3 **衰减不是状态**。衰减只降低排序权重（§3.6），不产生新状态、不改状态字段、不改变 V-A 可读性。任何"已衰减"的状态都是设计错误。
- I-4 只有 `情景` 层会自然过期；`语义` 层长期有效，直到被修正或删除（§3.1）。
- I-5 `已修正` 条目不参与过期扫描（它是历史记录）；只有 `生效` 情景条目会转入 `已过期`。

### 6.2 转换表（权威，测试照此写用例）

| ID | 起点 → 终点 | 触发者 | 触发条件 | 可逆性 | 依据 | 关联 AC |

## 7. 文案与降级规范

### 7.1 拒写（N-1 ~ N-6）的用户可见表现

判定原则：**用户是否显式要求写入**决定"静默"还是"回绝"。

| 编号 | 场景 | 用户是否显式要求记住 | agent 表现 |
| --- | --- | --- | --- |
| N-1 | 密钥/令牌/密码/私钥/连接串凭据 | 否 | **完全静默**：不写、不提示、不评论（避免暗示"我看见了"） |
| N-1 | 同上 | 是（"记住这个 key"） | 回绝一次：`这条不记：它看起来是凭据类信息，我不会写入记忆。当前对话照常可用。` 不复述密钥内容 |
| N-2 | 用户说"别记/不要保存/这段忘掉" | — | 受理：`好，这段不记。` 若该段已产生条目 → 追加 `已把刚才那条从记忆里移除。` |
| N-3 | 临时草稿/被标为"随口说的" | 否 | 静默不写 |
| N-3 | 同上 | 是 | `你说这是临时的，我先不记。要长期记的话说「这条要记住」。` |
| N-4 | 第三方个人信息（他人电话/住址/证件号） | 否 | 静默不写 |
| N-4 | 同上 | 是 | `这条不记：里面有别人的个人信息。` |
| N-5 | 敏感属性推断（健康/宗教/政治/取向等） | 任意 | 不写、不推断、不评论。用户显式要求时：`这类内容我不记。`（对应 W3） |
| N-6 | 对 agent 的负面情绪宣泄 | 任意 | 静默不写（避免形成偏误画像） |

**辅助约束**

- 拒写文案**不复述被拒内容**，尤其 N-1/N-4/N-5。只说类别，不引原文。
- 拒写**不产生条目、不产生"待确认"队列**；用户若坚持，下一次显式要求仍会再回绝一次（不回绝升级为存储）。
- 拒写必须留审计（原因类别 + 时间，无正文），支撑 §6.3 O-1 与 AC-7。

### 7.2 检索为空 / 超时 / 不可用的降级

**铁律：不得编造"我记得"。**以下三档必须严格区分，禁止用同一句话糊过去。

| 档 | 情形 | 普通对话中（用户没提记忆） | 用户显式查询记忆时 |
| --- | --- | --- | --- |
| D-1 | 检索正常、结果为空 | **不提示**，正常回答（AC-9 的"优雅降级"） | `我没有相关记录。` |
| D-2 | 检索超时/报错 | 静默按"无记忆"回答，**不外露错误**，仅记审计 | `记忆暂时读不到（超时），这次没法给你清单。可以稍后再问一次。` |
| D-3 | 功能被关闭 | 静默按"无记忆"回答 | `记忆已关闭，我现在没有可查的记忆。` |

补充规则：

1. **禁止的表述**（无论哪档都不许出现）：`我记得…`（当实际没检索到）、`之前你说过…`（无来源）、编造条目号、编造日期。
2. 超时阈值与降级路径由实现决定，但**用户侧只有上面三档文案**，不新增"部分结果""降级模式"等第四种状态（避免无法验收）。
3. 若某次回答**确实用了记忆**且用户追问依据 → 按 7.3 标注；若没用记忆，追问时必须明确 `这次没有用到记忆。`（不许含糊）。

### 7.3 "依据记忆"的标注格式（OQ-9=B：仅追问时给）

**触发**：用户问"你怎么知道的 / 你从哪知道的 / 什么时候记的 / 依据是什么"（AC-11）。

**格式（单条）**

```
依据记忆（第 3 条 · 语义 · 项目，2026-10-30 你说明发版流程时）：发版前必须先跑 pnpm build
```

**格式（多条）**

```
这次用了 2 条记忆：
- 第 3 条（语义 · 项目，2026-10-30）：发版前必须先跑 pnpm build
- 第 5 条（用户 · 2026-10-22）：注释一律写中文
```

**格式（本次未用记忆）**

```
这次没有用到记忆，是按你当前的指令直接回答的。
```

规则：

1. **只在追问时标注**；普通回答里不插入"根据记忆"（OQ-9=B / G-5）。
2. 标注必须含：序号、分层、作用域、来源时间、来源事件短语。**五要素**（D-8 X-7，以 DC-32 列举为准）缺一即不合格（AC-11）。
3. 若用户要求看原始来源片段（"原话是什么"）→ 给来源引用与该片段的相关表述；**不得伪造引用**，取不到时明确说 `这段来源我取不到了。`
4. 硬删条目的来源不可回溯（见 §10-C5）：应答 `这条已经彻底删除，来源不再保留。`
5. 标注里的序号必须与最近一次清单一致；若期间有新写入导致漂移，改用稳定标识：`依据记忆（标识 <id> · 语义 · 项目，…）`。

### 7.4 写入失败与不确定态

| 情形 | 文案 |
| --- | --- |
| 用户说"记住"但后台写入失败 | 下一次交互开头：`（上一条我没记住，可以再说一次，或换个说法）` |
| 用户说"记住"但语义被系统按"细化"合并了 | `已并入第 2 条：<合并后的完整内容>` |
| 写入被去重（完全重复） | `这条已经在记忆里了（第 2 条），我没重复记。` |

原则：**用户主动要求过的事，结果必须回告**（G-1）；自动写入失败则静默（G-5）。

### 7.5 删除相关文案表（汇总，便于测试逐条比对）

| 场景 | 文案 |
| --- | --- |
| 普通删除执行 | `已删除第 3 条（语义 · 项目）：<正文>` + `可恢复：回复「撤销」，或稍后说「看回收站」。` |
| 隐私删除确认 | `将彻底删除 1 条，不可恢复：` + 条目回显 + `确认请回复「确认彻底删除」；回复「取消」放弃。` |
| 隐私删除完成 | `已彻底删除 1 条。此操作不可撤销，该内容不会再出现在检索、清单或任何摘要中。` |
| 撤销成功 | `已恢复第 3 条（语义 · 项目），状态回到「生效」。` |
| 撤销不可用（已硬删） | `第 3 条已被彻底删除，无法恢复。` |
| 撤销需跨会话 | `这次不能直接撤销：撤销只在同一个会话里有效。不过它还在回收站，说「看回收站」可以恢复。` |
| 批量预览 | `将要删除 3 条，先确认：` + 列表 + `回复「确认」全部删除；回复「保留 4」排除某条；回复「取消」放弃。` |
| 批量完成 | `已删除 3 条（可恢复）。回复「撤销」可撤回，或说「看回收站」。` |
| 回收站入口 | `回收站 ｜ 共 2 条（可恢复，说「恢复第 N 条」或「全部恢复」）` |

> 撤销窗口说明（因无 UI 计时器，必须把"窗口"定义清楚）：**同一会话内**说"撤销"即可恢复最近一次删除；跨会话后改用"回收站 + 恢复第 N 条"，同样可恢复（只要未被硬删或保留期届满）。禁止实现"5 秒后 toast 消失"这类无对应物的机制，也禁止对用户宣称"你只有 5 秒"。软删保留期见 §11-Q2。

对话形态没有视觉层级、没有焦点、没有 hover，因此可访问性等价于**可判定性**。

| # | 要求 | 具体做法 | 验证方式 |
| --- | --- | --- | --- |

| A-2 | **可复述** | 序号 + 稳定标识双轨；破坏性操作回显正文（G-2/G-3） | 说"第 3 条"与说标识都能命中同一条 |

| A-4 | **不依赖 emoji 与列对齐** | L-1/L-3/L-6；不使用表格、不使用表情符号 | 在 60/80/120 列终端、等宽与非等宽字体下检查不错位、不丢字 |

| A-9 | **一致的作用域/分层用词** | 全程只用「项目/用户」「语义/情景」，不混用"全局/本地/知识库/重要度"等替代说法 | grep 用词 |

## 10. AC 冲突与形态替代方案（**判定口径以此为准**）

> **v2 修订（D-7）**：面板已纳入 MVP，本节前提由「纯对话形态」变为「对话 + 面板双通道」。以下 C-1~C-8 的**裁定结论全部继续有效**，但适用范围需按下方标注理解：
> - **C-1** 的「无筛选控件」裁定**仅约束对话通道**；面板**允许**真实筛选控件，但必须与对话限定词语义等价（D-7 S-2）。
> - 其余各条（C-2~C-8）为**跨通道通用**判定口径，两条通道均照此验收。

任务书要求：若"纯对话指令"无法满足某条 AC，必须显式标注冲突并给替代方案，不得假设有界面。以下按严重度排序，每条给：冲突描述 → 裁定 → 替代方案 → 测试口径修正。

### C-1 ⚠ AC-6「可按作用域/分层筛选」隐含筛选控件 → 形态转换

- **冲突**：AC-6 原句写"清单可按作用域/分层筛选"，在面板语境下指复选框/下拉。原 OQ-7=A 曾排除面板（**该前提已被 D-7 推翻**）。
- **裁定**：**不是不可满足，是需要把"筛选控件"翻译成"带限定词的追加查询"**。AC-6 的判定目标（"用户能只看到某一作用域/某一分层"）在对话形态下完全可达。
- **替代方案**：§5.8 限定词表。筛选是会话内临时上下文；`共 N 条` 按筛选后集合计；首行必须带限定词。
- **测试口径修正**：AC-6 第二条的 Then 改为——"用户说「只看项目级的」后，输出仅含项目级条目，且首行条数与项目级实际条数相等；再说「看全部」能回到全集"。**不要**断言存在筛选控件。

### C-2 ⚠ AC-6「条数与实际存储一致」× 分页上限 → 以"声明式总数"满足

- **冲突**：§6.2 规定"≤200 条分页"，且本设计默认每页 10 条；若字面理解"清单里出现所有条目"，两者矛盾。
- **裁定**：**"不多不少"约束的是计数准确性，不是单次输出的完整性**。一次输出 10 条但声明"共 25 条"不违反 AC-6；声明"共 10 条"而实际有 25 条才违反。
- **替代方案**：DC-10 —— 首行总数 + 分状态小计必须与实际相等（软删另列、不计入 N）；分页并集 = V-A 全集；末页有明确结束标记。
- **测试口径修正**：AC-6 第二句改为"首行声明的总数等于分状态小计之和，且等于 V-A 可见条目实际数；连续翻页后各页并集无重复无遗漏"。**不要**断言一次输出包含全部条目，也不要把软删计入 N。

### C-3 ⚠ AC-5「删除后从清单消失」× OQ-5=C「软删可恢复」→ 三视图隔离

- **冲突**：AC-5 要求删除后"从「你记得我什么」清单中消失"；OQ-5=C 要求普通删除可恢复。若可恢复就必须能看见，二者字面矛盾。
- **裁定**：**"清单"在 AC-5 中指 V-A 主清单**（用户常规视图）。可恢复性通过独立的 V-B 回收站提供，不污染主清单。
- **替代方案**：§3 可见性矩阵 + DC-09。V-A 永不出现软删条目；V-B 只出现软删条目。
- **测试口径修正**：AC-5 Then 拆两条断言——①V-A 与检索中该条目消失 ②V-B 中该条目存在且可恢复。**不要**断言"系统内不存在该条目"。

### C-4 ⚠ AC-6「不同作用域的记忆」× 会话作用域不持久

- **冲突**：AC-6 Given 要求"N≥3 条不同分层、不同作用域的记忆"。但 §3.4 规定 `会话` 作用域不持久化（B-3），实际持久作用域只有 `项目` / `用户`。
- **裁定**：**"不同作用域"在 MVP 中只能由 `项目` 与 `用户` 两个值构成**，`会话` 不参与。这不是降级，是 PRD 自身定义使然。
- **替代方案**：测试夹具用 2 作用域 × 2 分层覆盖（§5.3 样例即为此设计：V-A 6 条 + 回收站 1 条，覆盖 2 分层 × 2 作用域 × 4 状态）。
- **测试口径修正**：Given 改为"不同分层（语义/情景）× 不同作用域（项目/用户）"。**不要**构造会话作用域条目。

### C-5 ⚠ AC-11「来源片段引用」× 隐私硬删后不可追溯

- **冲突**：AC-11 要求任意生效记忆可给出来源引用；AC-5 要求硬删后内容不出现在任何衍生形态。硬删条目的来源引用是否保留？
- **裁定**：**删除后即不可追溯，且这不是 AC-11 的违反**——AC-11 的适用范围是"生效中的记忆"，硬删条目已不在该范围。
- **替代方案**：§7.3 第 4 条话术 `这条已经彻底删除，来源不再保留。`；审计只留"发生过 1 次隐私删除"。
- **测试口径修正**：AC-11 只对 `生效` 条目断言；新增一条负向断言——硬删后追问来源必须失败且不泄露内容。

### C-6 ⚠ OQ-5=C 未定义"撤销窗口"的时长 → 用会话边界替代计时器

- **冲突**：OQ-5=A 提到"短窗口内撤销"，C 定为双档但未给窗口数值；对话形态没有 toast 计时器。
- **裁定**：**窗口 = 同会话内的"撤销"快捷 + 跨会话的"回收站恢复"**，两者合起来覆盖"可恢复"，不引入计时器与过期 toast。
- **替代方案**：§7.5 文案表；不得向用户宣称任何具体秒数。
- **遗留**：软删条目在回收站的保留期未定 → 见 §11-Q2，需 product-manager 定值，**不阻塞 MVP**（可以先按"不过期"实现，只在文档标注待定）。

### C-7（安全设计，非 AC 冲突）序号漂移

- 说明：不是 AC 冲突，但纯对话形态特有风险，AC-2/AC-5 的"改第 N 条/删第 N 条"直接受影响。
- 处理：G-2 + DC-18 序号漂移保护（破坏性操作以回显正文为准）。
- 测试口径：构造"输出清单 → 插入新写入 → 说删第 3 条"，断言系统先回显当前第 3 条并要求确认。

### C-8（补充）「已过期」在小样本下与 V-A 折叠策略的张力

- 说明：§5.6 允许已过期超过 5 条时折叠汇总；AC-4 要求"在记忆列表中状态显示为已过期"。
- 裁定：折叠仅在 >5 条时发生，且计数与入口始终存在；`≤5` 条时逐条展示 `状态：已过期（…到期，不参与检索）`，满足 AC-4 字面要求。MVP 样本量下（30 天情景保留期）极少触发折叠。
- 测试口径：AC-4 用 ≤5 条已过期样本断言逐条展示；另用 >5 条样本断言折叠行存在且计数正确、`看已过期的` 能展开。
