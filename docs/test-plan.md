## 2. 判定口径：裁定如何落成断言

> **这是本计划最关键的一节。** 本节重申一条纪律：**不得按 PRD 字面写断言。** PRD 正文与 DECISIONS 冲突时一律按 DECISIONS；D-4 已裁定 8 条 AC 冲突，D-8 已裁定 9 条契约矛盾，D-9 已修订入口视觉。按字面写会**误报缺陷**，把正确实现判成失败。

### 2.1 D-4 的 8 条：❌ 禁止这样断言 / ✅ 必须这样断言

| 裁定 | ❌ 禁止（会误报） | ✅ 必须 | 关联用例 |
| --- | --- | --- | --- |
| **C-1** 筛选 | 对话通道断言「存在作用域/分层筛选控件」 | 对话通道：说限定词后**输出集合**只含该维度，首行 `共 N 条` 按筛选后集合计；说「看全部」回全集。面板通道：**允许真控件**，断言控件结果与对话限定词结果**集合与 N 逐项相等** | TC-AC6-02/03、TC-S2-01 |
| **C-2** 不多不少 | 「一次输出包含全部 N 条」；「清单条数 == 全库条数」 | ①`N == 生效 a + 已修正 b + 已过期 c`；②`N == V-A 可见集实际条数`；③软删 k 条**另行列示且不计入 N**；④翻页各页并集 == V-A 全集，无重复无遗漏；⑤末页有结束标记 | TC-AC6-04、TC-DC10-01~05 |
| **C-3** 从清单消失 | 「系统内不存在该条目」；「回收站也没有它」 | **拆两条**：①软删后 V-A 与检索不返回该条、N 减 1；②V-B **存在**该条且可恢复（恢复后回到删除前状态） | TC-AC5-01/02 |
| **C-4** 不同作用域 | Given 里构造 `session` 作用域条目 | 夹具只用 `project`/`user`；断言任何视图都不出现 `session` 作用域（类型层已不可能，见 `SCOPE` 枚举） | TC-AC6-05、TC-AC8-01 |
| **C-5** 来源可追溯 | 对硬删条目断言「来源仍可查」 | ①只对**生效**条目断言五要素齐备；②硬删后追问来源必须**失败且不泄露正文**（负向断言）；③审计只留「发生过一次隐私删除」，无正文无标识 | TC-AC11-01~04 |
| **C-6** 撤销窗口 | 「5 秒内可撤销」；断言倒计时元素；任何秒数 | ①同会话内「撤销」成功；②跨会话「撤销」不可用但回收站可恢复；③**负向断言**：撤销文案/UI 中不出现任何秒数、无倒计时/进度条计时器 | TC-AC5-05、TC-PC-06/28 |
| **C-7** 序号漂移 | 直接按序号删除而不校验回显 | 构造「清单 → 期间新增写入 → 删第 3 条」，断言系统**先回显当前第 3 条正文**并要求确认；未确认不执行 | TC-DES-01~03 |
| **C-8** 已过期展示 | 「一律折叠」或「一律逐条展示」 | ①≤5 条逐条出现 `状态：已过期（…到期，不参与检索）`；②>5 条折叠行存在且**计数与入口仍在**，N 与 c 不因折叠减小 | TC-AC4-02/03、TC-DC10-03 |

### 2.2 D-8 / D-9 追加的判定点（v1 未覆盖，v2 必测）

| 裁定 | 落到断言的方式 |
| --- | --- |
| **X-1** 「忘掉」档位 | 同一目标两轮对照：先「彻底删除」→ 断言 V-B **无**、不可恢复；重置后再「忘掉第 N 条」→ 断言 V-B **有**、可恢复。**两次结果必须不同**。另断言「忘掉关于 X 的全部」（批量）走软删 + 预览后执行 |
| **X-2** 筛选态 N | 断言 `N == 筛选后集合三态之和`，且**首行显示当前筛选条件**；未筛选时**不出现**限定词（负向断言） |
| **X-3** 折叠阈值 | 用夹具 **F-C2**（语义 4 过期 + 情景 4 过期，合计 8 > 5）：两通道**都必须折叠**。若实现按「单层内」（各 4 ≤5）→ 不折叠 → **P0 缺陷** |
| **X-4** 天数文案 | 先确认实现的实际清理行为，再断言文案与之匹配：实现 30 天清理 → 文案必须写 30 天，且 31 天前软删**必须已转硬删**；实现不过期 → 文案**不得出现任何天数**。**「写 30 天但 31 天仍可恢复」= P0** |

### 2.4 其他断言纪律

1. **只逐字断言契约文案**（DC-34 列出的那些）。非契约文案只断言「含关键信息项」。
2. **不断言视觉**：颜色/间距/字号/emoji/列对齐。状态判定走**三通道冗余**（`+ ~ - x` 字符 / `状态：` 行 / 小节标题）。
3. **不断言实现细节**：存储格式、索引算法、ID 编码、超时阈值、调度方式。
4. **时间相关不得等真实时间**：用 `service.setClock()` + `seed()` 的任意时间戳（§7 O-2 已实现）。
5. **「没有发生」也要断言**：静默、无幻觉、无死按钮、无回滚入口，都写成负向断言。
6. **每次执行留存原始输出快照**（清单全文、统计条文本、检索返回、审计行），缺陷报告必须附最小复现与原文。

## 3. 分层策略

| 层 | 名称 | 覆盖对象 | 执行方式 | 通过含义 | 当前可执行 |
| --- | --- | --- | --- | --- | --- |
| **L0** | 契约静态检查 | DC-01/02/09/27/28、PC-01/04/34、PE-13/19 | 源码 grep + 导出集合 + 枚举值断言 | 硬约束未违反（**不等于**功能正确） | ✅ |
| **L1** | 数据层单元 | 写入五道闸门、去重/冲突/纠错、状态机 9 转换、计数聚合、删除档位 | 直接构造 `MemoryService` + `seed()`，断言返回值与库状态 | 规则分支正确 | ✅ |
| **L2** | 集成（服务+HTTP） | 写入 → 存储 → 检索 → 三视图，四条读路径一致 | 同一 service 同时走工具与 HTTP 适配层，比对输出 | 单一事实来源成立 | ✅ |
| **L3** | 端到端·对话通道 | AC-1~AC-11 的用户可观察行为（**真实 harness 会话**） | 真实会话 + 文本断言 | 用户体验面达标 | ❌ **待 §6.5** |
| **L4** | 端到端·面板通道 | PC/PE 页面行为、键盘可达 | 真实 GUI（Web GUI + 已装插件） | 页面行为达标 | ❌ **待 §6.5** |
| **L5** | 双通道一致性 | S-1~S-5、跨通道交叉断言 | 同一意图两通道各一次，比对集合与 N | 无通道分歧 | ❌ **待 §6.5**（服务层近似可判，见 §3.1） |
| **L6** | 非功能 | 检索 P95、写入耗时、审计四类留痕、审计无正文 | 1 万条压测 + 审计查询 | 指标达标 | ⚠️ 性能 ✅ / 审计缺口 = **缺陷 N-2 待修**（§15） |

### 3.1 当前可执行边界的诚实说明

- **L1/L2 的「集成」不是「端到端」**：我用 `createTools()` + 合成 `ToolExec` 直接调工具，用假 `webServer` 捕获 handler 直接合成请求。这能抓「工具与 HTTP 两套实现漂移」，但**抓不到**「模型是否真的调了工具」「宿主是否真的把 turnTail 挂上去了」「pane 是否真的去重」。后者属 L3/L4。
- **L5 的服务层近似**：面板侧走 HTTP handler、对话侧走工具，两者共用同一个 `MemoryService`，因此 S-1/S-2 的**数据一致性**可以在 L2 判定；但「面板操作后对话侧**立即可见**」的**时序**（缓存、乐观更新）只有在真实 GUI 里才成立，属 L4/L5。
- **结论**：L0~L2 + L6 全绿**不构成验收**。验收必须含 L3+L4+L5 的真实链路证据。

**顺序理由**：先静态后动态（快的先排除）；先计数后行为（N 是坐标系）；先服务层后渲染层（渲染层只是同一份数据的第二个出口）；**L3/L4/L5 无法在插件装入前执行，因此排在阶段 11（阻塞，见 §11）**。

## 9. 失败判定规则

### 9.1 三档判定（**不存在第四档**）

| 判定 | 含义 | 报告里的写法 |
| --- | --- | --- |
| **通过** | 我跑出了证据，且断言全部成立 | 「通过 + 证据路径」 |
| **失败** | 我跑出了证据，且断言不成立 | 「失败 + 缺陷编号」（§9.5） |
| **未验证** | 因**观测面缺失 / 环境不可用 / 前置未满足**而无法执行 | 「未验证（原因）+ 解锁条件」 |

> **铁律一**：「未验证」**不是通过，也不是失败**。任何情况下不得把「未验证」写成「通过」，也不得因为「代码看起来对」就把未验证项折算成通过。观测面缺失 → **必须**判未验证（§7.3）。
>
> **铁律二（D-11 后新增，防止反向滥用）**：**「确认有缺陷」= 失败，不得改判「未验证」。** 两者边界：
>
> | 情形 | 判定 | 例 |
> | --- | --- | --- |
> | 有证据证明**行为与契约不符** | **失败** | N-1 关闭态仍列出条目；N-4 首行缺项目名 |
> | 有证据证明**能力缺失导致契约承诺无法兑现** | **失败**（D-11 N-3 的口径） | 开关指令无执行通道，但文案已承诺「说『开启记忆』可以打开」 |
> | **无法观测**（缺环境 / 缺观测口 / 前置不可构造） | **未验证** | L3/L4/L5 未装插件（U-1）；误记率无判定分母（U-8） |
>
> 换句话说：**「未验证」只能用于「我看不到」，不能用于「我看到了它不对」。** 用「未验证」掩盖已确认缺陷，是本计划最不能接受的错误。

## 10. 风险清单：最可能出缺陷的 5 处

### R-1 计数口径 DC-10：软删被算进 N，以及筛选/折叠/分页后的 N 重算（**最高**）

- **为什么最容易坏**：N 有 5 种取值场景（默认/筛选/折叠/切页签/空态），面板还有 4 处展示位（统计条、分组头小计、页签计数、分页器）都必须由同一份数据算出。任一处用「当前页条数」「全库条数」「含软删」就同时踩中 PC-09/10/12/13/11。
- **高发形态**：①软删计入 N ②筛选后仍显示全库 N ③折叠后 N 变小 ④分组小计与总数不同源 ⑤分页后 N 变成当页条数。
- **难发现原因**：默认态恰好正确（F-A 下 4+1+1=6），只有制造筛选/折叠/分页才暴露。
- **必测**：TC-DC10-01~05、TC-AC6-04、TC-PC-09~13。

### R-2 检索候选集未严格 ≡ {生效}

- **为什么最容易坏**：I-2 是 AC-2/3/4/5 的共同根基，而「排除」有 4 种来源状态，实现常在「已修正」上漏一处（新旧条目语义相近，混入后回答看不出错，只出现两个互斥答案）。
- **高发形态**：①纠错后仍返回旧条目 ②过期条目仍作为依据 ③软删条目在检索里复活 ④候选用「最近 N 条」而非状态过滤。
- **难发现原因**：单看回答像是「对的」，必须用「只应返回新值」的互斥断言才抓得到。
- **必测**：TC-DC25-01~04、TC-AC2-01/02、TC-AC3-01、TC-AC5-01。

### R-3 破坏性操作的三件事常常只做一半（回显 / 二次确认 / 序号漂移）

- **为什么最容易坏**：三件事分布在两通道四处（对话回显、对话确认、面板删除弹窗回显、面板勾选确认）。而 C-6 禁止用计时器兜底，撤销只能靠会话边界，实现容易误加 toast 倒计时。
- **高发形态**：①弹窗只显示「第 3 条」②模糊肯定「好/嗯」被执行 ③游离「确认」触发上一次未完成的操作 ④toast 写「5 秒内可撤销」⑤跨会话「撤销」仍成功。
- **难发现原因**：正常路径全对，只有制造漂移与模糊确认才暴露。
- **必测**：TC-DES-01~08、TC-AC5-04/05、TC-PC-06/07/24/28、TC-S2-02。

### R-4 双通道一致性：面板改动未即时反映到对话

- **为什么最容易坏**：S-1 要求同一份数据，实现常见「前端先改页面再异步同步」。这类缺陷在单通道测试里 100% 看不见。
- **高发形态**：①面板删完对话还能检索到（或反之）②面板编辑后旧内容仍被检索 ③面板默认硬删 ④两通道 N 不一致 ⑤面板筛选项与对话限定词结果集不同。
- **难发现原因**：必须先 A 再立刻 B，且要跨通道比对同一意图。**当前 L5 不可执行（§6.5），这是最大的盲区**。
- **必测**：TC-S1-01~05、TC-S2-01~04、TC-S3-01~03。

### R-5 状态表达「三通道冗余」退化 + 失败态被空态吞掉

- **为什么最容易坏**：图形化面板天然倾向用颜色表达状态，而 PC-16/19 要求去色仍可判定；同时 DC-16/PC-37/PE-16 要求「读取失败」与「空」必须不同文案，最省事的写法就是失败也显示空态（用户会以为记忆被删光，是**最严重的产品事故**）。
- **高发形态**：①只有彩色胶囊没有 `+~-x` 与状态文字 ②`已修正` 缺「被第 N 条取代 + 日期」③`已过期` 缺「到期日 + 不参与检索」④加载失败显示空态文案 ⑤面板渲染失败提示「请改用对话」（把面板当唯一路径，违反 S-4）。
- **难发现原因**：正常数据下配色好看、文案通顺，只有去色/注入失败才暴露。
- **必测**：TC-PC-03/04/10/16~19、TC-AC9-01/02、TC-ENTRY-08。
