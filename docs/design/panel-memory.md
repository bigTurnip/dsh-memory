## 1. 范围与边界

### 1.1 面板是什么

面板是**同一份记忆的第二个入口**，能力范围 = 查看 + 管理（改 / 删 / 恢复）。**它不是数据源，不是编辑器，也不是新的业务对象。**

- **是**：查看清单、按作用域/分层/状态筛选与搜索、看条目详情与来源、改内容、改作用域、普通删除、彻底删除、回收站恢复、看某条目的变更记录。
- **不是**：写入记忆的入口（写入仍由对话驱动）、类型分类器、全局审计时间线、批量导入导出、跨项目浏览。

### 1.2 边界表

| # | 边界 | 依据 | 落地表现 |
| --- | --- | --- | --- |
| PB-1 | **无类型**：不出现任何类型标签、类型名、类型筛选 | D-3 / DC-01 | 筛选控件只有作用域 / 分层 / 状态三个下拉；全站 grep 不到类型枚举 |
| PB-2 | **只有分层**：语义 / 情景；程序不进 MVP，**不出现空分组** | D-3 / DC-02 / DC-11 | 某层 0 条时整层标题都不渲染 |
| PB-3 | **只有两个持久作用域**：项目 / 用户；会话作用域不出现 | D-1 / DC-04 | 作用域下拉只有三项：全部/项目/用户 |
| PB-4 | **面板不是写入入口** | D-7「面板是增强入口，不是唯一入口」 | 无"新建记忆"按钮；空态给的是"去对话里说点什么" |
| PB-5 | **不得手动改分层** | D-5 Q3 | 编辑弹窗里分层是只读锁定字段，并解释原因 |
| PB-6 | **不得查看已硬删内容** | AC-5 / R-3.6.4 | 硬删条目在任何页签、搜索、详情、变更记录中均不出现 |
| PB-7 | **不得回滚到旧版本** | DC-27 | 变更记录页无"恢复此版本"按钮，只有只追加的版本链 |
| PB-8 | 不做多身份、不做跨设备、不做自动执行 | D-1 / W4 / W5 | 无登录态、无同步入口、无写文件动作 |

### 1.3 反目标（明确不要的设计）

- ❌ 不要"记忆卡片墙 / 时间轴 / 图谱 / 热度云"这类把记忆可视化的产物——MVP 没有对应业务语义。
- ❌ 不要"重要程度 / 置信度 / 记忆强度"进度条——`DC-28` 明确衰减不是状态，画出来就是误导。
- ❌ 不要"全选 → 批量删除全部"——批量必须有命中预览（DC-22），一键清空没有预览就不合格。
- ❌ 不要把"类型"换个名字（`tag` / `kind` / `category`）加回来。
- ❌ 不要给删除配倒计时进度条或"5 秒后消失"的 toast 计时器（C-6：禁止宣称具体秒数）。

## 2. 信息架构

### 2.1 导航结构

```
记忆管理面板
├── 页签 A · 记忆清单（V-A 主清单，默认）
│     └── 条目抽屉：详情 / 来源 / 使用情况 / 状态历史 / 操作
│           ├── 编辑弹窗
│           ├── 普通删除弹窗（软删，可撤销）
│           ├── 彻底删除弹窗（二次确认，不可逆）
│           └── 跳转页签 C（该条目的变更记录）
├── 页签 B · 回收站（V-B）
│     ├── 恢复（单条 / 全部）
│     └── 彻底删除（同一二次确认弹窗）
└── 页签 C · 变更记录（V-C）
      └── 只追加的版本链（当前版本 + 历史版本）
```

**层级只有两层**：页签 → 覆盖层（抽屉/弹窗）。**没有第三级页面，没有面包屑。** 这是刻意的：记忆管理的任务量很小，多一层导航就多一次迷路。

### 2.2 页面骨架（1280px 及以上）

```
┌───────────────────────────────────────────────────────────────────────┐
│ 顶栏：页面标题 + 视图代号(V-A) │ 作用域锚点(项目·dsh-momery) │ 面板说明 │
├────────────┬──────────────────────────────────────────────────────────┤
│            │                                                          │
│  左侧导航   │  ① 统计条：共 N 条（+ 生效 a / ~ 已修正 b / - 已过期 c）  │
│            │     + a+b+c=N 公式 + 回收站另有 k 条（不计入 N）          │
│  A 记忆清单 │  ────────────────────────────────────────────────────────│
│  B 回收站   │  ② 工具条：搜索 │ 作用域 │ 分层 │ 状态 │ 清空筛选        │
│  C 变更记录 │  ────────────────────────────────────────────────────────│
│            │  ③ 语义层（分组头：生效 a · 已修正 b · 已过期 c）         │
│  ─────     │       ┌ 生效 k 条 ─────────────────────────────────┐      │
│  作用域锚点 │       │ 3+  测试命令是 vitest                       │      │
│  项目        │       │     作用域 项目 │ 分层 语义 │ 来源 … │ +生效 │      │
│  dsh-momery │       │                          [详情][编辑][删除]  │      │
│            │       └─────────────────────────────────────────────┘      │
│            │       ┌ 已修正 k 条 / 已过期 k 条（含折叠行）────────┐     │
│            │  ④ 情景层（同上）                                        │
│            │  ⑤ 分页：第 1–10 条 · 共 N 条 · 每页 10 条 [上一页][1][下一页]│
└────────────┴──────────────────────────────────────────────────────────┘
```

### 2.3 三页签 = 三视图（DC-09 v2）

| 页签 | 视图 | 包含的状态 | 检索返回 | 依据 |
| --- | --- | --- | --- | --- |
| **A 记忆清单** | V-A 主清单 | 生效、已修正、已过期 | 仅「生效」 | §3 可见性矩阵 |
| **B 回收站** | V-B | 仅「已删除-软删」 | 否 | OQ-5=C |
| **C 变更记录** | V-C | 某条目的全部历史版本 | 否 | AC-3 |

**硬约束（不可新增第四种视图）**：页签数量必须恰为 3。以下都是**明确禁止**的第四视图，即使听上去合理：

- ❌ "全部记忆（含已删除）"合并视图
- ❌ "已硬删审计日志"页
- ❌ "记忆统计 / 仪表盘"页
- ❌ "待确认记忆"页（OQ-11=A 全自动写入，不存在待确认队列）
- ❌ 全局时间线（变更记录必须**先选定条目**，见 §5.3）

> 理由：第四视图会立刻破坏 DC-10 的 N（哪条算"在清单里"？）和 C-3 的"V-A 专指"裁定。三条通道共用一份数据，视图必须互斥且穷尽。

### 2.4 为什么把"筛选"放在页签内而不是侧栏

对话通道的筛选是**会话内临时上下文**（§5.8 规则 1）。面板的筛选状态同样**不持久化、不写 URL、刷新即回全部**，以此保持两条通道的语义一致（S-2：同样是"临时限定"，不是"保存的视图"）。如果做成可保存的筛选视图，就变成了第四种视图语义。

## 3. 页签 A：记忆清单（核心页面）

### 3.1 页面目标

让用户在**一屏内**回答三个问题：① 我一共有多少条记忆？② 现在哪些话是算数的？③ 哪条不对，我要改它。

### 3.2 统计条（首行）

```
共 6 条    [+ 生效 4]  [~ 已修正 1]  [- 已过期 1]    4 + 1 + 1 = 6
           回收站另有 1 条已删除（可恢复），不计入上面的 6 条 · 去回收站
```

| 元素 | 规则 | 依据 |
| --- | --- | --- |
| `共 N 条` | N = V-A 可见集实际条数 = 生效 + 已修正 + 已过期。**不是**全库条数 | DC-10 |
| 三个状态胶囊 | 每个都带状态符号（`+ ~ -`）+ 状态名 + 数字；**符号是冗余通道，颜色只是增强** | DC-13 / §8.4 |
| 公式 `a + b + c = N` | 明写出来，让用户/测试一瞥即可验算；不满足时视为实现缺陷 | DC-10 / C-2 |
| 回收站计数 | **单独一行**，明写"不计入"，并给去回收站的入口 | DC-10 / C-3 |

> **这是 DC-10 在面板上的唯一实现点。** 页面任何其他地方（页签角标、分页器、分组头）的数字**必须由同一份数据算出**，不得另写。原型里刻意调用同一个 `updateStats()`，并在每处 `console.assert(a+b+c===n)`。

### 3.3 工具条

| 控件 | 控件形态 | 选项 | 说明 |
| --- | --- | --- | --- |
| 搜索框 | text | 匹配内容与来源事件描述 | 输入即筛（防抖 ≥200ms）；匹配面与对话 F6 命中面一致 |
| 作用域 | select | 全部 / 项目 / 用户 | 对应对话「只看项目级的」「只看用户级的」 |
| 分层 | select | 全部 / 语义 / 情景 | 对应「只看语义层」「只看情景层」 |
| 状态 | select | 全部 / 生效 / 已修正 / 已过期 | 对应「看已过期的」 |
| 清空筛选 | button | — | 对应「看全部」 |

**S-2 语义等价**：四个控件的**每一种组合**都必须在对话通道上有等价表达。做不到等价就不许加控件（§4.3 有对照表）。

### 3.4 计数口径落到页面（DC-10 的页面级验证）

这是本设计最容易被实现错的地方，单独写死：

| 场景 | N 应当等于 | 常见错误 |
| --- | --- | --- |
| 默认态 | 生效 + 已修正 + 已过期 | 把软删算进 N（错）；把已过期排除出 N（错） |
| 有筛选 | **筛选后集合**的上述三态之和 | 仍显示全库 N（错）；显示"共 10 条（当前页）"（错） |
| 已过期被折叠 | 含被折叠的条目（折叠只是不逐条渲染） | 折叠后把 N 减小（错） |
| 切换页签 B | 页签 B 的计数独立，与 N 无关 | 用 B 的数字覆盖 A（错） |
| 空态 | N = 0，且文案逐字 | 用空态冒充读取失败（错，DC-16） |

> 测试可直接用原型复现：默认数据 `4+1+1=6`，切"已过期折叠"数据 `4+1+7=12`。

### 3.5 分组与排序

1. **分组只按分层**：语义 → 情景。**不出现空分组**（某层 0 条则整块不渲染）。
2. **层内再分状态小节**：生效 → 已修正 → 已过期；小节标题带符号 + 名称 + 条数。
3. **同状态内**按最近确认时间倒序。
4. **分页不切断分组**：跨页时新页首重印分层与状态小节标题（DC-15）。
5. 已过期 **V-A 全清单合计超过 5 条**时折叠（见 §5.8；**D-8 X-3：与对话通道统一为全清单口径，原「单层内」作废**）。

### 3.6 条目卡（清单中的一条）

```
┌──────────────────────────────────────────────────────────────────┐
│ 3+   测试命令是 vitest                              [详情][编辑][删除] │
│      作用域 项目 │ 分层 语义 │ 来源 2026-10-30 你纠正…（你纠正过的）  │
│      [+ 生效]                                                     │
└──────────────────────────────────────────────────────────────────┘
```

**三通道冗余（沿用端上，不因图形化而丢）**

| 通道 | 生效 | 已修正 | 已过期 | 已删除（软删，仅页签 B） |
| --- | --- | --- | --- | --- |
| ① 序号后缀字符 | `+` | `~` | `-` | `x` |
| ② 状态标签文字 | `生效` | `已修正（2026-10-30 被第 3 条取代）` | `已过期（2026-11-19 到期，不参与检索）` | `已删除（可恢复）` |
| ③ 所在状态小节标题 | `生效 k 条` | `已修正 k 条` | `已过期 k 条` | 仅在页签 B |
| （增强）④ 颜色/底色 | 绿 | 蓝灰 | 琥珀 | 中性灰 |

**验收断言**：把浏览器颜色全部去掉（或用高对比模式）后，仍能从 ①②③ 判定每条的四个状态之一。

`已修正` / `已过期` 的附加信息是**强制的**，不可只显示状态词：已修正必须带"被第 N 条取代 + 日期"，已过期必须带"到期日 + 不参与检索"（DC-14）。理由见上一版 §5.5：不写清楚，用户无法判断"哪个说法现在有效"。

### 3.7 分页

| 项 | 规则 |
| --- | --- |
| 每页 | **10 条**（跨分组连续计数） |
| 单页内完整性 | 一个条目不得跨页拆开 |
| 末页 | 显式"已到最后一页" |
| 折叠条目 | 不占页内位置，但**仍计入 N 与状态小计**（分页器明写这一点） |

## 4. 操作交互

### 4.1 条目详情（抽屉）

从右侧滑出，宽度 `min(560px, 92vw)`，不整页跳转（保住用户的位置感）。

| 区块 | 内容 |
| --- | --- |
| 头部 | 第 N 条 · 分层 · 作用域；正文标题 |
| 状态提示 | 已修正/已过期时顶部给一条说明性 callout（含取代关系或到期日） |
| 内容与归属 | 内容、分层（标注"不可手动修改"）、作用域、状态标签、**稳定标识** |
| 来源 | 产生时间、触发原因（+ **来源可信度**：你明确说的/你纠正过的/系统推断的，属 PRD §3.7 的「来源类型」字段，与已取消的条目分类无关）、**来源引用可跳转** |
| 使用情况 | 复用次数、最近命中时间；并注明"查看清单不计入复用次数"（DC-23） |
| 状态历史 | 状态链：创建 → （生效→已修正 / 生效→已过期） |
| 底部操作 | 编辑 / **恢复（仅「已过期」）** / 变更记录 / 删除（软删）/ 彻底删除 |

**「恢复」的适用面**：只出现在「已过期」条目上——T-4 把它转回生效并按 `episodic_retention_days` 重新计时（D-5 Q4）。「已修正」不给恢复：历史只追加、不回滚（DC-27）；「生效」无需恢复。

**稳定标识只在详情出现**（D-6 Q6），主清单不展示。

### 4.2 编辑

| 字段 | 可编辑 | 说明 |
| --- | --- | --- |
| 内容 | ✅ | 必填，200 字上限，实时字数计数 |
| 分层 | ❌ **锁定** | 只读展示 + 解释"分层由写入侧判定（D-5 Q3）；如需换层请删除后用想要的说法重新记" |
| 作用域 | ✅ | 项目 / 用户 二选一（对应对话 F4-c「这条升到用户级」） |

**保存后的行为**（必须与对话一致）：
- 旧内容 → `已修正`，**不删除**，进入变更记录，并标注"被哪条取代、何时"。
- 新内容 → `生效`；**当次会话内立即可检索**（DC-26）。
- 弹窗内**事前告知**这个后果，不要保存后才弹提示。

### 4.3 筛选控件 ↔ 对话限定词对照（S-2）

| 面板操作 | 对话等价表达 | 结果必须一致 |
| --- | --- | --- |
| 作用域=项目 | 「只看项目级的」 | 条目集合相同、首行/N 相同 |
| 作用域=用户 | 「只看用户级的」 | 同上 |
| 分层=语义 | 「只看语义层」 | 同上 |
| 分层=情景 | 「只看情景层」 | 同上 |
| 状态=已过期 | 「看已过期的」 | 同上 |
| 清空筛选 | 「看全部」/「不要筛选了」 | 回到全集 |
| 搜索关键词 | 「忘掉关于 X 的」的命中面 / 追问时的检索 | 匹配面一致（正文、来源事件描述） |

**不提供的筛选维度**：类型（不存在）、重要程度（不存在）、敏感等级（属内部字段，不作筛选入口）。

### 4.4 普通删除（软删）

**必须包含 4 件事**（缺一即不合格）：

1. **回显目标正文**——不是"第 3 条"，而是把正文、状态、作用域、来源时间摆出来（DC-17）。这是 DC-18「序号漂移保护」在页面上的等价物：面板里序号会随筛选/分页变化而漂移。
2. **说清后果**——"立即从检索和清单中消失，但进入回收站保留 30 天，随时可恢复"。
3. **说清这是跨通道的**——"删除后说『你记得我什么』也不会再看到它"（S-1 / S-2）。
4. **默认档必须是软删**——按钮文案是"确认删除"，不是"确认彻底删除"。

### 4.5 彻底删除（隐私删除）

在 4.4 的 4 件事之外，再加 2 件：

5. **显式勾选确认**——一个 checkbox：「我确认要彻底删除上面这条内容，理解此操作不可撤销」。**模糊肯定不视为确认**（DC-20），所以未勾选时主按钮 `disabled`；不能用"再点一次同一个按钮"代替勾选。
6. **逐条列出不可逆后果**——不出现在检索/清单/变更记录/任何摘要；不进回收站；审计只留"发生过一次隐私删除"，不留正文。

### 4.6 批量遗忘

- 入口：页签 A 的批量入口（对话侧等价于「忘掉关于 X 的记忆」）。
- **先预览后执行**：预览列表与实际执行的是同一份清单；**取消勾选 = 排除**（等价于对话的「保留 4」）。
- 条数实时更新；排除到 0 条时主按钮禁用。
- 预览里若含用户级条目，**必须提示**该条跨项目生效（否则用户以为只影响本项目）。
- 默认软删；要硬删必须逐条走 4.5。

### 4.7 撤销

- 删除成功后给一条 toast：`已删除第 3 条（语义 · 项目）：测试用例…` + **撤销**按钮。
- **不宣称任何秒数**（C-6）。toast 上写的是"本会话内有效"，不是"5 秒内有效"，也**不做倒计时进度条**。
- 跨会话后走回收站恢复，这条路始终存在。

### 4.8 设置抽屉（页头入口，**不是第四个页签**）

设置改的是「插件怎么工作」，不是「记忆长什么样」。它不进页签体系：

- 页签**恰三个**是 PC-01 / HC-3 的硬约束（`role="tab"` 计数有断言），第四个页签会被判违反契约；
- 看记忆与配记忆不应在同一视觉层级上打架。

**入口与形态**

| 项 | 规格 |
| --- | --- |
| 入口位置 | 面板页头右侧（`.mem-head`），按钮文案「设置」，`min-height:32px`，`data-testid="mem-settings-open"` |
| 关闭态也有入口 | 必须。否则「记忆已关闭」之后在面板上没有任何路把它重新打开 |
| 形态 | 遮罩抽屉（`.mem-settings`，max-width 640px），不整页跳转 |
| 头部文案 | 「记忆设置」+ 一句「这些是插件设置，不是记忆条目（不会进入清单，也不会被检索）。保存后立即生效。」 |

**七行控件**（类型与范围来自 `src/shared/settings.ts`，界面不自己定义）

| 行 | 控件 | 说明文案要点 |
| --- | --- | --- |
| 记忆功能 | 开关 | 关闭后不写入、不检索，清单与面板都不可查 |
| 写入提示 | 开关 | 只是不提示，写入照常 |
| 每会话提示次数 | 数字（1–20，单位「次」） | 前 N 次各一行提示，之后静默 |
| 回收站保留 | 数字（1–365，单位「天」）+ 「不过期」复选框 | 勾选后数字框置灰；文案不再出现天数（X-4） |
| 情景记忆保留 | 数字（1–3650，单位「天」） | 到期转「已过期」，可恢复并重新计时 |
| 情景衰减窗口 | 数字（1–3650，单位「天」） | 只影响排序，不改状态 |
| **自动召回注入** | 开关（默认关） | 开启后每轮按你的输入召回最多 3 条注入上下文；关闭记忆时永不注入 |

每行带一句「改了会发生什么」，**不写实现细节**（不出现表名、字段名、算法名）。

**召回预览**：抽屉底部一段输入框 + 「预览」。用一段自己的话试，下面按注入格式原样输出——**预览与真实注入共用 `formatRecallText()`**，所以「看到的」就是「会注入的」。空命中时明写「没有命中任何生效记忆：开启后这一轮不会注入任何内容」，而不是留一片空白。

**校验与反馈**

- 保存是**全有或全无**：任一项越界则整批不落库，错误条（`role="alert"`）里点名是哪一项、范围多少；
- 保存成功后 toast：`设置已保存（N 项），立即生效。`，并**重取清单**：`enabled` / `retention_days` 会直接改变首行计数与文案，不重取就会显示过期状态。

**不准做的事**

- 不准在抽屉里提供「新建记忆」或「编辑记忆」——设置抽屉不是写入入口（PB-4 不因它开口子）。
- 不准把设置渲染在页签里充当第四视图（PC-01 / HC-3）。

## 5. 页签 B / C 与全部页面状态

### 5.1 页签 B：回收站

| 列 | 内容 |
| --- | --- |
| 条目 | 序号`x` + 正文 + 来源 |
| 作用域 / 分层 | 项目/用户 · 语义/情景 |
| 删除时间 | 精确到分钟 |
| 保留期 | 进度条 + "剩余 29 / 30 天" |
| 操作 | 恢复 / 彻底删除 |

- 顶部常驻说明：**保留期 30 天**后自动转彻底删除（D-5 Q2）；**恢复后重新计时 30 天**（D-5 Q4）。
- 页头给"全部恢复"。
- 回收站为空：`回收站是空的。` + 一句解释。
- **回收站不出现**：已硬删条目（它们不存在于任何视图）。

### 5.2 保留期的呈现注意

进度条**只表达"剩余天数占比"**，不得做成"倒计时动画"、不得每秒刷新、不得用红色闪烁。它是静态信息，不是紧迫感道具。

### 5.3 页签 C：变更记录

**V-C 是"某个条目"的视图**，因此：

- 从条目详情/条目卡进入时，直接展开该条目的版本链；
- 直接切到页签 C 时，展示"选择条目"的列表（条目 + 版本数 + 当前状态 + 查看入口），而不是全局时间线（那是第四视图，禁止）。

版本链的表达：

```
● v4 · 当前生效 · 2026-10-30 15:12
  + 测试命令是 vitest
    来源：… · 取代 v3
○ v3 · 已修正 · 2026-10-28 09:40
  ~ 测试命令是 pnpm test
    被 v4 取代 · 原因：同会话内用户显式否定（隐式纠错）
○ v2 · 已修正 · 2026-10-25 18:03
  ~ 测试命令是 jest
    被 v3 取代 · 原因：用户显式修改
```

**必须**：① 只追加，A→B→A 显示为三/四个节点，历史不被改写；② 每个历史节点标注"被谁取代 + 何时 + 原因"；③ 明确写"只有当前版本参与检索"；④ **没有"回滚到旧版"按钮**。

### 5.4 九类页面状态（逐一有稿）

| # | 状态 | 页面表现 | 依据 |
| --- | --- | --- | --- |
| 1 | 加载中 | 骨架屏（3 张卡），**延迟 ≥300ms 才出现**以避免闪烁；`aria-live` 播报"正在读取记忆…" | 新增要求 |
| 2 | 空（无任何记忆） | `目前没有记录任何关于你的记忆。`（**逐字**）+ 副行 + "去对话里说点什么" | DC-16 |
| 3 | 加载失败 | `记忆暂时读不到（超时），这次没法给你清单。` + 重试；**禁止套用空态文案** | DC-16 / DC-31 |
| 4 | 筛选后为空 | 说明当前筛选条件 + "筛选后为空 ≠ 没有记忆" + 清空筛选 | §5.7 |
| 5 | 折叠（已过期 >5） | 折叠行：`已过期另有 k 条未展开（本页展示 5 / N 条）` + "展开全部" + "折叠不影响计数" | D-4 C-8 |
| 6 | 禁用 | 主按钮 `disabled`（如未勾选彻底删除确认、批量排除到 0 条、"只有 1 个版本"的变更记录按钮） | — |
| 7 | 已修正 / 已过期条目 | 底色区分 + 状态标签带取代/到期信息 | DC-14 |
| 8 | 回收站为空 | `回收站是空的。` | §5.7 |
| 9 | 功能关闭（记忆被用户关闭） | 全页面替换为关闭态说明 + "在对话里说『开启记忆』可打开"。**不给半残的清单** | §7.2 D-3 |

> 未列入但同样要处理的边界：**权限不足**在 D-1（本机单用户）下不存在，故无此态；**部分加载失败**按 PRD 只有三档降级，不新增第四档。

## 6. 双通道一致性（S-1 ~ S-5 的落地）

### 6.1 能力矩阵（这是 S-3 的直接产物）

| 能力 | 对话 | 面板 | 说明 |
| --- | --- | --- | --- |
| 查看清单 / 筛选 / 搜索 | ✅ | ✅ | 面板用控件，对话用限定词，结果必须一致 |
| 看条目详情与来源 | ✅ | ✅ | 面板额外交互更省事 |
| 修改内容 | ✅ | ✅ | 都产生"旧→已修正、新→生效" |
| 修改作用域 | ✅ | ✅ | — |
| **手动改分层** | ❌ | ❌ **禁止** | D-5 Q3 |
| **按类型筛选/查看类型** | ❌ | ❌ **禁止** | D-3 |
| **查看已硬删内容** | ❌ | ❌ **禁止** | AC-5 |
| **回滚到旧版本** | ❌ | ❌ **禁止** | DC-27 |
| 普通删除（软删） | ✅ | ✅ | 默认档一致 |
| 彻底删除（硬删） | ✅ | ✅ | 都需二次确认 |
| 批量遗忘 | ✅ | ✅ | 都必须先预览 |
| 恢复（撤销 / 回收站） | ✅ | ✅ | — |
| **写入新记忆** | ✅ | ❌ | 面板不是写入入口（§1.2 PB-4） |
| **追问"依据记忆"** | ✅ | ❌ | 属对话上下文能力 |

### 6.2 S-1 单一事实来源

- 面板所有读写走同一份记忆数据；**面板无本地缓存副本**，不做"先改页面再同步"。
- 面板操作成功后，**同会话内对话侧立即可检索到新结果**（DC-26 的跨通道版本）。

**验收点（可直接写成用例）**

| 编号 | 步骤 | 断言 |
| --- | --- | --- |
| S1-1 | 面板改第 3 条内容 → 立刻在对话问同话题 | 只返回新内容；旧内容不返回 |
| S1-2 | 面板普通删除第 5 条 → 对话说「你记得我什么」 | 清单不含第 5 条，N 减 1，页签 B 出现该条 |
| S1-3 | 对话里删掉第 2 条 → 刷新面板 | 页签 A 不含第 2 条；页签 B 含；N 减 1 |
| S1-4 | 对话写入一条新记忆 → 刷新面板 | 页签 A 出现，N 加 1，状态=生效 |

### 6.3 S-2 语义等价

同一个意图在两条通道上结果必须一致，**尤其"删除"**：

- 面板「删除」= 对话「删掉第 N 条」= **软删**。
- 面板「彻底删除」= 对话「彻底删除」= **硬删**。
- **禁止**：面板默认硬删、或面板删除后对话侧仍能检索到、或两条通道产生不同的目标状态。

### 6.4 S-3 不可绕过

面板**不得**因为"有界面"就提供对话禁止的能力。落地方式：

- 编辑弹窗的分层是**只读组件**（不是 disabled 的 select——disabled 的 select 会让人以为某个权限下可启用）。
- 筛选下拉里**物理上没有**类型选项。
- 页签 B 的"彻底删除"是**删"软删条目"**，不是"查看硬删内容"。
- 全站无"版本回滚"按钮。

### 6.5 S-4 降级

| 场景 | 要求 |
| --- | --- |
| 纯终端环境（无 GUI） | 上面矩阵里"对话 ✅"的全部能力可用；**不存在只有面板能做的事** |
| 面板打不开/报错 | 记忆功能不受影响，对话侧行为完全不变 |
| 面板加载失败 | 页面给重试入口；**不得**提示"请改用对话删除"这类把面板当唯一路径的文案 |

> 这就是 PB-4（面板不提供写入）的另一个好处：面板整个挂掉，写入链路毫发无伤。

### 6.6 S-5 判定口径不变

`D-4` 的 **C-2（计数准确性）** 与 **C-3（V-A 专指）** 在面板上原样生效：

- C-2：统计条的 N 与三个分项必须等于实际集合（§3.4）。
- C-3：AC-5 的"从清单消失"指**页签 A 消失**；页签 B 必须仍有它且可恢复。测试**不得**断言"系统内不存在"。

### B 计数与分页（PC-09 ~ PC-15）

| ID | 约束 | 验证 |
| --- | --- | --- |
| PC-09 | 首行必须给 `共 N 条（生效 a / 已修正 b / 已过期 c）`，且 **a+b+c=N=V-A 实际条数** | 6 条 + 1 软删 → N=6 |

## 8. 视觉规范

### 8.1 设计基调

**安静的档案柜**，不是仪表盘。理由：记忆是用户私人的、低频但高敏感的内容，界面应当像"查看一份关于自己的记录"，而不是"监控一个系统"。因此：低饱和、弱阴影、单强调色、不用图标堆装饰、不用大面积色块。

## 9. 可访问性

### 9.1 结构语义

| 项 | 做法 |
| --- | --- |
| 地标 | `aside`（导航）/ `header` / `main`；顶部有"跳到主内容"跳转链接 |
| 页签 | `role="tablist"` + `role="tab"` + `aria-selected` + `aria-controls`，面板 `role="tabpanel"` + `aria-labelledby`；**roving tabindex**（只有选中项 `tabindex=0`） |
| 分组 | 每个分层一个 `section` + `aria-labelledby` 指向其 `h2` |
| 条目 | `article` + `aria-label`（"第3条，语义，项目，生效，测试命令是 vitest"）——**屏幕阅读器不读装饰性符号**，序号与状态用 ARIA 标签补全 |
| 状态符号 | 视觉上是 `+ ~ - x`，但标 `aria-hidden="true"`，真实语义由标签文字承担 |
| 表格 | `caption`（`sr-only`）+ `th scope="col"` |
| 抽屉/弹窗 | `role="dialog"` `aria-modal="true"` `aria-labelledby`；打开时焦点移入，关闭后**焦点回到触发元素** |
| 统计条 | `aria-live="polite"`——筛选后条数变化会被播报 |

### 9.2 键盘

| 键 | 行为 |
| --- | --- |
| `Tab` / `Shift+Tab` | 按视觉顺序移动（导航 → 统计 → 工具条 → 清单条目 → 分页） |
| `↑ ↓ ← →` | 页签间移动（垂直布局用上下，横向页签条用左右） |
| `Home` / `End` | 首/末页签 |
| `Enter` / `Space` | 激活按钮、勾选 |
| `Esc` | 关闭最上层浮层（弹窗优先于抽屉） |

**焦点顺序原则**：清单内每条卡片内是 `详情 → 编辑 → 删除`，与视觉从左到右一致；**破坏性按钮不抢焦点**，不与详情并列在首位。

### 9.3 屏幕阅读器要点

- 状态标签朗读为"生效"，不朗读 `+`；但 `aria-label` 里包含"第3条…生效"，保证信息完整。
- 破坏性弹窗打开时**先播报标题**，再让用户读到回显条目；回显区用 `echo__label` 的文本节点"将删除的目标条目"作为语义开头，不靠视觉分组。
- 条数变化用 `aria-live="polite"`，不用 `assertive`（避免打断用户朗读正文）。

### 9.4 不依赖颜色的强制校验

| 断言 | 做法 |
| --- | --- |
| 去色后仍能分辨 4 个状态 | 状态词 + 序号后缀字符 + 小节标题三重存在 |
| 高对比/强制颜色模式下 | 不依赖 `background-image` 渐变承载状态（已修正/已过期用左边浅渐变，**纯装饰**；去掉后靠标签仍可判定） |
| 200% 缩放 | 无横向滚动、无文字裁切（字号用 px，但容器用弹性布局） |
| 触控目标 | 所有可点元素 ≥44×44px（按钮 `min-height:44`；图标按钮 36px 视觉 + 44px 命中区） |

### 10.1 原型里刻意做的 5 个细节

1. **计数不写死**：统计条、页签角标、分组小计、分页器全部由同一份数据渲染，每次渲染 `console.assert(a+b+c===n)`——防止"演示数据好看但口径错了"。
2. **折叠是真的**：切到"已过期折叠"是把 6 条数据真的加进集合，`N` 变成 12，折叠行显示"另有 2 条未展开"，**不是伪造一个折叠条**。
3. **彻底删除不能一键完成**：必须勾选确认框，主按钮才可用——原型里这段交互是真的禁用。
4. **分层是只读组件**：编辑弹窗里分层长得像输入框但不可交互，并直接写了原因，避免"看起来能改"。
5. **抽屉被宿主裁剪**：关闭态滑出视口右侧，用 `overflow:hidden` 的宿主包住，窄屏不会撑出横向滚动条。
