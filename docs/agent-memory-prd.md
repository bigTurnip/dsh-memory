### 0.3 一句话定义

> 记忆不是"把历史对话塞回上下文"，而是**可检索、可控制、可遗忘的第二次认知**。它让 agent 在新会话里"认得你"，同时让你随时知道它记得什么、能改、能删。

## 1. 问题与用户价值

### 1.1 目标用户与角色

| 角色 | 描述 | 主要诉求 |
| --- | --- | --- |
| 主力用户（P0） | 长期在同一个项目/工作目录下使用 agent 的个人开发者，单会话高频、跨会话连续 | 不想每次重复交代背景；agent 别把上次的结论忘掉 |
| 轻度用户（P1） | 偶尔使用，偏好稳定但不愿做配置 | 少解释、别出错、别有隐私风险 |
| 共享设备/团队场景（P2） | 同一台机器或同一工作目录被多人使用 | 记忆不能串味；可清理 |

> 【推断】目标用户以"单人多项目长周期使用"为主。若实际主要是"多人共享同一工作区"，§3.4 作用域与 §5 `OQ-10` 的结论会显著变化，请优先确认。

### 1.2 当前没有记忆时的损失（场景化）

| # | 场景 | 现状 | 损失 |
| --- | --- | --- | --- |
| S1 | 新会话继续昨天的任务 | 需要重新贴上下文、重新解释约定 | 每次 3–10 分钟重复沟通，且常漏讲关键约束 |
| S2 | 用户明确说过的偏好 | "用 pnpm 不用 npm""注释写中文""别自动改版本号"——下次照旧忘记 | 需要反复纠正，信任感下降；重复犯错 |
| S3 | 上次踩过的坑 | 同一个报错第二次仍然重复排查 | 浪费 token 和时间，agent 显得"没有成长" |
| S4 | 项目硬约束 | 目录规范、分支策略、禁止改动的文件 | 违反约定造成返工，严重时破坏仓库 |
| S5 | 用户要求"别记这个" | 无从表达，也无从验证 | 隐私焦虑，用户不敢在对话里说敏感信息 |

### 1.3 记忆要解决什么（本版承诺的价值）

1. **跨会话连续性**：新会话无需重复交代，agent 能主动取回与当前任务相关的历史结论与约束。
2. **偏好与约束的沉淀**：用户纠正过一次，就不必纠正第二次（在冲突规则允许的范围内，见 §3.3）。
3. **减少重复踩坑**：同类问题再次出现时能复用已验证的结论与规避方式。
4. **可控与可遗忘**：用户随时能看见、能改、能删；系统默认不记不该记的东西。

### 1.4 记忆明确不解决什么（非目标）

- **不做"无限上下文"**：记忆不是把全部历史塞进 prompt，常驻上下文不是本方案路径。（【已确认】）
- **不做通用知识库/联网检索**：世界知识不是"关于你的记忆"。
- **不替代项目内文档与代码**：仓库里已有的事实以仓库为准，记忆只做"索引与提醒"。
- **不做跨用户共享的记忆市场**：本版无任何跨用户共享。
- **不做自动修改用户文件/配置**：记忆只影响 agent 的理解与建议。
- **不保证 100% 召回**：记忆是增益能力，缺失应优雅降级而不是报错。

### 1.5 成功指标（建议值，【推断】，需用户确认口径）

| 指标 | 定义 | 建议目标（MVP 观察期） |
| --- | --- | --- |
| 记忆命中率 | 需要历史信息的会话中，成功取回相关记忆的比例 | ≥ 60%（人工抽样 50 会话） |
| 重复纠正率 | 同一偏好被用户纠正 ≥2 次的会话占比 | 相对基线下降 ≥ 50% |
| 误记率 | 被用户判定"不该记"的记忆条目占比 | ≤ 5% |
| 用户干预率 | 用户对记忆执行编辑/删除的频次 | 观察值，无硬目标（过高说明抽取质量差） |
| 检索延迟 | 见 §6.2 | P95 ≤ 300ms |

## 2. 范围与优先级

采用 MoSCoW 分级。**MVP = 全部 Must 项**；Should 项可在 MVP 后紧接交付；Could 项按资源决定；Won't 为本版明确不做。

### 2.1 Must（MVP 必须，缺一不可上线）

| ID | 需求 | 说明 |
| --- | --- | --- |
| M1 | 语义记忆写入 | 从对话中抽取偏好/项目事实/约束/结论，带显著性筛选，落库为独立条目 |
| M2 | 记忆检索（按需） | 以能力/工具方式被调用，返回相关记忆 + 来源标注；**不常驻上下文** |
| M3 | 跨会话生效 | 新会话无需用户重复交代即可取回相关记忆 |
| M4 | 记忆可查看 | 用户可问"你记得我什么"，得到条目清单（含分层、内容、作用域、来源、时间） |
| M5 | 记忆可编辑 | 用户可修改某条记忆的内容 |
| M6 | 记忆可删除 | 用户可删除单条 / 按范围批量删除，删除后不再被检索到 |
| M7 | 写入白名单边界 | 密钥类、用户明确要求"别记"的内容不写入（见 §3.2） |
| M8 | 冲突与纠错 | 新信息与旧记忆冲突时按规则处理，且用户后续纠正能生效（见 §3.3） |
| M9 | 作用域隔离 | 记忆按作用域隔离，不跨用户/跨项目错误串用（见 §3.4） |
| M10 | 记忆操作可审计 | 每次写入/检索/编辑/删除可追溯（见 §6.3） |

### 2.2 Should（P1，MVP 后紧接）

| ID | 需求 | 说明 |
| --- | --- | --- |
| S1 | 情景记忆（事件层） | 记录"某天做了什么、结论是什么"，带自然过期 |
| S2 | 遗忘机制（衰减 + 过期） | 未被复用的记忆自动降权/过期，避免无限膨胀 |
| S3 | 记忆管理界面 | 列表 + 筛选 + 编辑 + 删除的可视化面板（替代纯对话指令） |
| S4 | 记忆来源回溯 | 每条记忆可跳转到产生它的对话/片段 |
| S5 | 检索结果的使用标注 | agent 在回答中标注"依据记忆 X"，让用户可质疑 |
| S6 | 导入/导出 | 记忆可导出为可读文件、可再导入（迁移与备份） |

### 2.3 Could（按资源决定）

| ID | 需求 |
| --- | --- |
| C1 | 程序记忆（技能/流程沉淀，见 §3.1） |
| C2 | 记忆画像（"关于我的档案"汇总视图） |
| C3 | 记忆冲突的用户确认交互（逐条确认覆盖） |
| C4 | 记忆质量反馈（点赞/点踩/报错，用于调优抽取） |
| C5 | 定时摘要（把零散情景记忆压缩为一条语义记忆） |

### 2.4 Won't（本版明确不做）

| ID | 不做的事 | 理由 |
| --- | --- | --- |
| W1 | 把全量历史对话注入上下文 | 与"按需检索"路径冲突，成本与噪声不可控 |
| W2 | 跨用户共享记忆池 | 隐私风险，本版无此场景 |
| W3 | 自动推断敏感属性（健康、宗教、政治倾向等）并存储 | 高风险低收益，明确禁止 |
| W4 | 云端同步/多端漫游 | 超出本版范围，且有合规成本 |
| W5 | 记忆驱动自动执行动作（如自动改配置、自动提交） | 不可逆风险，需单独设计确认机制 |
| W6 | 对用户隐藏的记忆 | 与"可查看"验收标准直接冲突，永不做 |

## 3. 关键业务规则

### 3.1 记忆分层与职责边界

| 层 | 存什么 | 生命周期 | 是否跨会话 | MVP |
| --- | --- | --- | --- | --- |
| 工作记忆 Working | 当前会话的上下文、临时中间结论 | 会话结束即失效 | 否 | 已有能力，本版不改造 |
| 情景记忆 Episodic | 发生过的事：某次排查过程、某次决策及其结论 | 中短期，自然过期 | 是 | Should（S1） |
| 语义记忆 Semantic | 稳定事实与偏好：技术栈偏好、"这个项目的测试命令是 X"、硬约束 | 长期，直到被修正或删除 | 是 | **Must** |
| 程序记忆 Procedural | 可复用的做法：某类任务的标准流程、"这个仓库发版走哪几步" | 长期，随实践修正 | 是 | Could（C1） |

**层间规则**

- R-3.1.1【已确认】工作记忆不进入持久层；只有经过显著性筛选的内容才可能升为情景或语义记忆。
- R-3.1.2【推断】一条情景记忆被多次复用（≥3 次，建议值，见 `OQ-3`）后可被提升为语义记忆；提升动作不删除原情景条目。
- R-3.1.3 ~~语义记忆的分类对齐本机既有能力 `kb_remember` 的四分类~~ **【已作废，见 DECISIONS.md D-3】**：本条不再生效。记忆条目**不设类型字段**，不区分结论/修正/偏好/教训；分层（episodic/semantic/procedural）是该条目唯一的结构性归类。
- R-3.1.4【已拍板 OQ-8 = A】程序记忆**不纳入 MVP**，MVP 只交付语义记忆（Must）+ 情景记忆（Should S1）；AC-12 不启用。

### 3.2 写入规则：写什么、不写什么

**写入判定为"是"的必要条件（全部满足）**

| # | 条件 | 说明 |
| --- | --- | --- |
| W-a | 与"用户/项目"相关，而非通用世界知识 | 通用知识走检索，不进记忆 |
| W-b | 具有跨会话复用价值 | 一次性的、只对当前回合有意义的结论不写 |
| W-c | 可由对话原文支撑 | 每条记忆必须能指回来源片段，禁止无源生成 |
| W-d | 未被既有记忆覆盖（去重） | 重复内容不新增条目，只更新复用计数 |

**显著性（salience）信号【推断，权重待设计确认】**

用户显式表达（"记住""以后都用""别再"）> 用户的纠正行为 > 反复出现的偏好 > agent 自行推断的结论。agent 不应把"猜测"写成与"用户明说"同等强度的记忆，二者需在条目上区分（见 §3.7 `source_type`）。

**硬性不写清单（【已确认】边界，命中即拒绝写入）**

| # | 不写的内容 | 处理 |
| --- | --- | --- |
| N-1 | 密钥、令牌、密码、私钥、连接串中的凭据 | 拒绝写入；若已在上下文中，不作为记忆条目 |
| N-2 | 用户明确说"别记/不要保存/这段话忘掉" | 拒绝写入；且需支持对该段内容的显式遗忘（见 §3.6） |
| N-3 | 临时草稿、被用户标记为"随口的"内容 | 拒绝写入 |
| N-4 | 第三方的个人可识别信息（他人的电话、住址、证件号等） | 拒绝写入 |
| N-5 | 敏感属性推断（健康、宗教、政治、性取向等） | 拒绝写入（对应 W3） |
| N-6 | 用户对 agent 的负面情绪宣泄 | 不写（避免形成偏误画像） |

> 边界判定口径：无法确定是否属于 N-1/N-3 时，**默认不写**（fail-closed）。【推断，建议】

### 3.3 去重、冲突与纠错

| 情形 | 规则 | 用户可观察结果 |
| --- | --- | --- |
| 完全重复 | 不新增条目，更新最近确认时间与复用次数 | 记忆列表条数不变，"最近确认"时间更新 |
| 语义等价（同义改写） | 同上，保留原始来源 | 同上 |
| 直接冲突（新旧互斥） | 见下方冲突策略 | 检索时只返回一方 |
| 细化补充（新信息是旧信息的补充） | 合并到同一条目或建立关联 | 检索时能同时返回 |
| 用户显式纠错 | 旧条目置为"已被修正"，新条目生效（**不依赖类型标签，见 D-3**） | 后续检索只返回新条目；旧条目在列表中显示为"已修正" |

**冲突处理策略**【待拍板 `OQ-4`，以下为推荐】

- 推荐：**新覆盖旧 + 保留被覆盖记录（不物理删除）+ 明确时间戳**。理由：记忆的价值在于"当前有效"，让用户看到完整变更史比保留多条互斥记忆更有用；保留历史可支撑"为什么它现在这么认为"。
- 备选 A：保留两条，检索时都返回并标注时间，由模型判断——风险是同一问题得到自相矛盾的答案。
- 备选 B：冲突时不写入，转人工确认——安全但打断体验，MVP 不建议。
- **强约束（不随选项变化）**：无论选哪种策略，用户显式纠错（"不对，是 X 不是 Y"）必须在**当次会话内立即生效**，不得等待下一轮或后台任务。

### 3.4 作用域

| 作用域 | 含义 | 典型内容 | 默认 |
| --- | --- | --- | --- |
| session | 仅当前会话 | 工作记忆，不持久化 | 不持久 |
| project | 绑定当前工作目录/项目 | 测试命令、目录规范、技术栈约束 | 见 `OQ-2` |
| user | 跨项目、绑定使用者 | 语言偏好、沟通风格、通用工作习惯 | 见 `OQ-2` |
| global | 全局共享（多项目可见） | 本版不提供（对应 W2 的弱化形态，见 `OQ-6`） | 不启用 |

- R-3.4.1【已确认】记忆不得跨用户泄漏：A 用户的记忆不得在 B 用户的会话中被检索到。
- R-3.4.2【推断】检索时的作用域优先级：session > project > user。project 命中优先于 user 命中；同内容冲突时按 §3.3 处理。
- R-3.4.3【待拍板】跨项目复用（用户级记忆在进入新项目时是否默认生效）见 `OQ-6`。

### 3.5 检索规则

| # | 规则 | 用户可观察结果 |
| --- | --- | --- |
| R-3.5.1 | 【已确认】按需检索，不常驻上下文 | 上下文不被记忆条目占用；仅在需要时调用 |
| R-3.5.2 | 检索结果必须带来源（条目 ID + 产生时间 + 来源片段引用） | 用户问"你从哪知道的"时有据可查 |
| R-3.5.3 | 检索为空时优雅降级 | agent 正常回答，不报错、不编造"我记得" |
| R-3.5.4 | 检索结果不得改变用户的原始指令语义 | 记忆是参考，不是覆盖当前指令；当记忆与当前指令冲突，**当前指令优先** |
| R-3.5.5 | 【推断】延迟量级见 §6.2；超时必须有降级路径 | 见 AC-10 |
| R-3.5.6 | 【待拍板】是否在回答中显式标注"依据记忆"见 `OQ-9`（Should S5） | — |

> 关于 R-3.5.4 的说明：用户当前说的"用 npm"必须压过记忆里的"用 pnpm"，同时该冲突应被记为一次纠错（进入 §3.3）。

### 3.6 遗忘规则

| 机制 | 触发 | 效果 | MVP |
| --- | --- | --- | --- |
| 显式删除 | 用户指令或界面操作 | 立即从检索结果中消失；保留方式见 `OQ-5` | **Must** |
| 过期 | 达到生命周期上限（情景记忆默认 30 天，建议值，见 `OQ-3`） | 不再参与检索，列表中标为"已过期" | Should |
| 衰减 | 长期未被复用（默认 90 天未被检索命中，建议值） | 检索排序权重下降，仍可被查看 | Should |
| 批量遗忘 | "忘掉关于 X 的所有记忆" | 按关键词/时间/作用域批量命中并删除，删除前展示命中清单 | Should |

- R-3.6.1【已确认】删除必须**立即生效且可验证**：删除后同一会话内再次检索不到，且"你记得我什么"不再列出。
- R-3.6.2【推断】删除默认不物理销毁原始对话记录（那是另一份数据），但记忆条目本身必须不可再被检索。
- R-3.6.3【待拍板】软删/硬删与可恢复性见 `OQ-5`。
- R-3.6.4【推断】被删除的记忆不得通过"摘要/画像"等衍生视图复活。

### 3.7 记忆条目字段（业务含义，非技术 schema）

| 字段 | 含义 | 必填 | 备注 |
| --- | --- | --- | --- |
| 条目 ID | 稳定标识 | 是 | 用户可见，用于指代"第 3 条" |
| ~~类型~~ | ~~四分类~~ | — | **【已删除，见 DECISIONS.md D-3】**：不设类型字段，不得引入类型枚举 |
| 分层 | episodic / semantic / procedural | 是 | §3.1；MVP 实际只出现 episodic 与 semantic |

| 来源类型 | 用户显式 / 用户纠正 / agent 推断 | 是 | 决定可信度展示 |
| 来源引用 | 产生它的对话/片段引用 | 是 | 支撑 W-c，可跳转（S4） |

## 4. 验收标准（Given/When/Then）

> 每条可被 test-engineer 直接转成用例；前置条件中"已开启记忆"指 `OQ-1` 的结论已落地。带 ⭐ 为队长明确要求覆盖的六项。

### AC-1 ⭐ 跨会话生效

- **Given** 用户在会话 A 中说明了项目约束"这个仓库发版必须先跑 pnpm build"，并已被写入记忆
- **When** 用户开启新的会话 B（上下文完全干净），并询问"发版要注意什么"
- **Then** agent 能检索到该记忆并在回答中体现"先跑 pnpm build"，且该结论与用户原话一致（不得改写语义）
- **And** 若会话 B 中用户未提及相关话题，该记忆**不出现**在上下文中（验证不常驻）

### AC-2 ⭐ 用户改偏好后生效

- **Given** 记忆中已有"用户偏好用 pnpm"
- **When** 用户在同一会话中明确说"以后用 npm，不用 pnpm 了"
- **Then** 记忆被更新（旧条目状态转为"已修正"或按 `OQ-4` 结论处理），新条目为"偏好用 npm"
- **And** 同一会话内下一次相关检索返回"用 npm"，**不再**返回"用 pnpm"
- **And** 跨到新会话 C 时仍为"用 npm"

### AC-3 ⭐ 冲突覆盖

- **Given** 存在两条互斥信息（记忆："测试命令是 jest"；用户当前说"测试命令是 vitest"）
- **When** 用户提出新信息
- **Then** 按 §3.3 选定策略处理后，检索结果**只返回一个确定性答案**（vitest），不得同时返回两个互斥选项
- **And** 被覆盖的记录可在记忆中查到变更来源与时间（不静默消失，除非 `OQ-4` 选择丢弃）

### AC-4 ⭐ 遗忘生效（过期 / 衰减）

- **Given** 一条情景记忆已超过保留期（见 `OQ-3`），且期间从未被检索命中
- **When** 用户提出与该情景相关的问题
- **Then** 该记忆不再作为依据出现在回答中；在记忆列表中状态显示为"已过期"
- **And** 该记忆不参与排序，但仍可被用户查看与手动恢复/删除
- **And** 衰减场景：未过期但长期未命中的记忆，排序权重低于近期命中记忆（可用同等问题两次检索的排序对比验证）

### AC-5 ⭐ 隐私删除

- **Given** 记忆中有一条用户想抹除的条目
- **When** 用户说"彻底删掉我刚才说的那条（非凭据内容，如家里 WiFi 名）/把关于 X 的记忆删掉"（**D-8 X-9：原「数据库密码」示例作废**——凭据按 N-1 拒绝写入，不存在删除路径；密码场景只用于 AC-7 不得写入验证）
- **Then** 该条目在同一次会话内即从检索结果与"你记得我什么"清单中消失
- **And** 再次检索相关关键词时**不返回**该条目，agent 不得声称"我记得"
- **And** 被删除内容不出现在任何衍生视图（摘要、画像）中
- **And** 删除操作在审计日志中留痕（记录"已删除"，但不记录被删的敏感正文）

### AC-6 ⭐ 记忆可查看

- **Given** 已存在 N（N≥3）条不同分层（语义/情景）、不同作用域的记忆
- **When** 用户问"你记得我什么"
- **Then** 返回清单，每条包含：分层（语义/情景）、内容、作用域、来源（何时因何事产生）、当前状态
- **And** 清单可按作用域/分层筛选，且条数与实际存储一致（不多不少）
- **And** 无记忆时返回明确的空状态文案（"目前没有记录任何关于你的记忆"），而非报错或沉默

### AC-7 不该记的边界

- **Given** 用户在对话中粘贴了一段包含 API Key 的配置，或明说"这段别记"
- **When** 系统执行写入判定
- **Then** 不产生任何包含该内容或可反推出该内容的记忆条目
- **And** "你记得我什么"中不出现该内容
- **And** 无法判定是否敏感时采取不写（fail-closed）

### AC-8 作用域隔离

- **Given** 用户在项目 P1 中存有项目级记忆，且用户级偏好为"回答用中文"
- **When** 用户切换到项目 P2
- **Then** P1 的项目级记忆**不出现**在 P2 的检索结果中；用户级偏好仍生效
- **And** 不同用户身份之间，任何记忆均不可互见

### AC-9 检索失败 / 降级

- **Given** 记忆检索超时或返回错误
- **When** 用户提出一个本可受益于记忆的问题
- **Then** agent 正常回答（不阻塞、不报错堆栈外露），且不编造记忆内容
- **And** 该次失败被记录到可观测指标（§6.3）

### AC-10 性能

- **Given** 记忆条目数在 1 万条以内
- **When** 执行一次检索
- **Then** P95 耗时 ≤ 300ms（建议值，见 `OQ-3`/§6.2 确认）
- **And** 写入抽取为异步，不阻塞当轮对话响应；写入在会话结束后 30s 内可被下一次检索命中

### AC-11 来源可追溯

- **Given** 任意一条生效中的记忆
- **When** 用户追问"你怎么知道的/什么时候记的"
- **Then** 能给出产生时间与来源对话/片段引用，且引用内容确实包含该结论的依据

### AC-12 程序记忆（仅当 `OQ-8` 判定纳入 MVP 时启用）

- **Given** 某类任务已被用户确认过标准流程
- **When** 用户下次发起同类任务
- **Then** agent 能复用该流程，且流程变更以新版覆盖旧版（同 §3.3 冲突规则）

## 5. 开放问题清单（需用户拍板）

> 以下问题我不替你决定，只给推荐。**每条都会改变范围、核心流程或验收结论**，建议在进入设计前逐条确认。可回复"按推荐"批量采纳。

### OQ-1 记忆默认是否开启？

- **影响**：决定首启体验、隐私默认值、验收前置条件（全部 AC 都假设已开启）
- **选项**：A. 默认开启，可一键关闭　B. 默认关闭，用户显式开启后才写入　C. 分级：项目级默认开、用户级默认关
- **推荐：A**。理由：记忆的价值在于"用户没意识到要开"时就在起作用；B 会让 MVP 的验证成本极高（大部分用户不会开）。隐私焦虑用"可查看/可删除/不记敏感信息"来兜底，而不是靠默认关闭。
- **不决策的后果**：验收无法编写前置条件；实现方案两条路线差异大。

### OQ-2 新记忆的默认作用域是什么？

- **影响**：跨项目行为、串味风险、检索优先级（R-3.4.2）
- **选项**：A. 默认 project（跟随工作目录），显式偏好才升为 user　B. 默认 user，项目相关内容显式降为 project　C. 每条写入时由抽取结果自行判定，不设默认
- **推荐：A**。理由：越"项目相关的硬约束"越常见且越不能串味；把串味代价高的一侧设为默认更安全。C 看似智能，但错误的作用域难以被用户发现和纠正。
- **不决策的后果**：AC-8 无法定稿；"用户偏好为什么在新项目不生效"会成为高频投诉。

### OQ-3 时间参数（保留期、衰减窗口、延迟预算）取什么量级？

- **影响**：AC-4、AC-10 的具体数值；存储增长
- **选项**：A. 采用本文建议值（情景 30 天 / 衰减 90 天 / 检索 P95 300ms）　B. 更保守（情景 7 天 / 衰减 30 天）　C. 更宽松（情景 90 天 / 衰减 180 天）　D. 全部做成用户可配，默认为 A
- **推荐：A，并在 Should 阶段演进到 D**。理由：先有确定值才能测；MVP 阶段暴露配置项会放大复杂度。
- **不决策的后果**：AC-4 不可执行；遗忘机制无法验收。

### OQ-4 记忆冲突时如何处理？

- **影响**：§3.3、AC-3；用户对"它到底记哪个"的信任
- **选项**：A. 新覆盖旧 + 保留变更记录（旧条目标"已修正"）　B. 两条共存，检索都返回并标时间　C. 冲突不写入，转交用户确认
- **推荐：A**。理由：用户要的是"当前有效答案"；B 会产出自相矛盾的回答，C 在 MVP 阶段会频繁打断。保留变更记录已满足可追溯。
- **不决策的后果**：A/B 的实现与测试完全不同，AC-3 的 Then 无法确定。

### OQ-5 删除是软删还是硬删？

- **影响**：AC-5 的判定、可恢复性、合规表述
- **选项**：A. 默认硬删（不可恢复），用户可在短窗口内撤销　B. 默认软删（可在回收站恢复，30 天后清理）　C. 双档：普通删除软删，隐私删除硬删
- **推荐：C**。理由：普通误删需要可恢复，隐私诉求需要"真的没了"。若只能选一个，选 A 更符合"我的数据我做主"。
- **不决策的后果**：AC-5 无法表述"删除后是否还能恢复"，测试结论模棱两可。

### OQ-6 用户级记忆是否跨项目自动生效？

- **影响**：§3.4、AC-8；跨项目"认得我"的体验强度
- **选项**：A. 自动生效（语言/风格类偏好优先）　B. 进入新项目时提示一次"是否沿用"　C. 不自动，需用户在新项目手动导入
- **推荐：A，仅限无冲突的偏好类**。理由：语言与沟通风格跨项目几乎总是成立；项目事实类必须留在 project 内，两者需在规则上分开（本推荐已内含该约束）。
- **不决策的后果**：R-3.4.3 悬空，AC-8 的作用域边界无法固定。

### OQ-7 用户如何访问记忆（入口形态）？

- **影响**：M4/M5/M6 的实现形态、MVP 工作量、designer 的输入
- **选项**：A. 仅对话指令（"你记得我什么""改掉第 3 条"）　B. 仅可视化面板　C. 两者都要（指令 + 面板）
- **推荐：A 作为 MVP，B 排到 Should（S3）**。理由：指令形态可以最快打通"可读可编辑可删"的验收闭环，且不依赖前端改造；面板是体验增强而非能力前提。
- **不决策的后果**：MVP 工作量差一个量级，designer 无法开始设计契约。

### OQ-8 程序记忆是否纳入 MVP？

- **影响**：范围（§2.3 C1）、AC-12 是否生效
- **选项**：A. 不纳入，MVP 只做语义 + 情景　B. 纳入，但仅记录不自动执行　C. 纳入且自动复用
- **推荐：A**。理由：程序记忆的"什么算一个流程"极难定义，且自动复用一旦错会影响整条工作流，风险远高于收益；先让语义+情景跑通再评估。
- **不决策的后果**：范围膨胀；AC-12 需要启用与否悬而未决。

### OQ-9 agent 回答时是否显式标注"依据记忆"？

- **影响**：S5 是否进 MVP；用户信任与噪声
- **选项**：A. 始终标注　B. 仅在用户追问时给出　C. 不标注，只保证可查
- **推荐：B**。理由：每条回答都插"根据记忆"会显著增加噪声；但用户追问时必须能立刻答出（AC-11 已约束）。
- **不决策的后果**：S5 归属不明，验收里"可质疑性"强弱无标准。

### OQ-10 是否存在"多人共用同一工作目录/同一身份"的场景？

- **影响**：§1.1 目标用户、§3.4 隔离粒度、AC-8
- **选项**：A. 不存在，本机单用户　B. 存在，需要多身份隔离　C. 存在但可接受共用（不做额外隔离）
- **推荐：A（若为真）**。理由：多身份隔离会把作用域与认证一起拉进 MVP，成本高。若实际是 B，则 §3.4 与 AC-8 需要重写，请明确告知。
- **不决策的后果**：隔离要求可能被低估，导致返工。

### OQ-11 记忆写入是否需要用户逐条确认？

- **影响**：写入流程、打扰程度、误记率
- **选项**：A. 全自动，事后可查看可改　B. 高显著性的逐条确认，其余自动　C. 全部需确认
- **推荐：A**。理由：逐条确认会让"记忆"变成负担，用户会直接关掉功能；用 M4/M5/M6 的可控性替代事前确认。
- **不决策的后果**：交互流程（尤其 designer 的输入）无法确定。

### OQ-12 成功指标是否采用 §1.5 的建议口径？

- **影响**：上线后的验收判据、是否需要埋点
- **选项**：A. 采纳建议值　B. 只保留"误记率 ≤5%"与"检索延迟"两个硬指标　C. 暂不设指标，先观察
- **推荐：B**。理由：命中率与重复纠正率依赖人工抽样，成本高；误记率与延迟客观可测，足以守住底线。
- **不决策的后果**：无法判断 MVP 是否"成功"，只能判断"完成"。

## 6. 非功能要求

### 6.1 隐私与安全

| # | 要求 | 可验证方式 |
| --- | --- | --- |
| P-1 | 记忆属于用户：可读、可编辑、可删、可导出（导出为 Should） | AC-5/AC-6 + 导出功能验收 |
| P-2 | 不记敏感内容（§3.2 N-1~N-6），判定不确定时 fail-closed | AC-7 |
| P-3 | 无隐藏记忆（W6）：任何被用于回答的记忆都必须可被用户查看 | 抽查：回答中每个记忆依据都能在清单中找到 |
| P-4 | 删除后不可通过检索或衍生视图复现 | AC-5 第三条 |
| P-5 | 记忆内容不因"方便"被发送到未声明的外部服务【推断，需与实现确认边界】 | 实现评审时确认 |

### 6.2 性能（【推断】建议值，见 `OQ-3`）

| 指标 | 建议目标 | 说明 |
| --- | --- | --- |
| 检索延迟 | P95 ≤ 300ms，P99 ≤ 800ms（万条量级） | 超出则必须走降级（AC-9） |
| 写入延迟 | 异步；当轮对话不被阻塞 | 会话结束后 30s 内可被检索到 |
| 记忆容量 | 单用户有效条目 ≥ 1 万条不显著劣化 | 超出由遗忘机制控制 |
| 列表查询 | "你记得我什么"首屏 ≤ 1s（≤200 条分页） | 分页而非全量返回 |

### 6.3 可观测性

| # | 要求 |
| --- | --- |
| O-1 | 每次写入留痕：时间、分层、作用域、来源引用、是否被拒绝（拒绝需记录原因类别，不留敏感正文） |
| O-2 | 每次检索留痕：查询意图、命中条目 ID、耗时、是否被实际采用 |
| O-3 | 每条记忆可回答"最近一次被使用是什么时候"（支撑衰减与用户质疑） |
| O-4 | 编辑/删除留痕：操作时间、目标条目 ID、操作类型（不含被删正文） |
| O-5 | 可统计：写入量、拒绝量、命中率、延迟分位、误记反馈数 |
| O-6 | 审计日志保留期待定（建议 90 天，见 `OQ-3`） |

### 6.4 可用性与降级

- 记忆能力不可用时，agent 必须表现为"没有记忆的 agent"（正常对话），而不是报错或半残状态。
- 空状态（无任何记忆）必须有明确文案，不得留白或显示内部错误。
- 对用户的记忆反馈（"记住这个"）应有轻量确认（如"已记住：xxx"），让写入可被感知——**与 OQ-11 的"自动写入"不冲突**：写入自动，但用户主动要求记住时需要给出受理结果。

### 6.5 兼容与迁移

- ~~语义记忆四分类必须与既有 `kb_remember` 对齐~~ **【已作废，见 DECISIONS.md D-3】**：记忆条目不设类型枚举，不与 `kb_remember` 四分类对齐。知识库资料与记忆条目是两套独立数据，不做自动互转。
- 本版不要求与外部记忆格式互通；导出格式由实现决定，但必须是人类可读的文本形态。
